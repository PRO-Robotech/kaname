# Смена ключа обёртки второго фактора

Секрет кода по времени каждого человека лежит в базе **обёрнутым**: AES-256-GCM под ключом из
перечня `authn.second-factor-encryption-key-hex` (переменная `KANAME_SECOND_FACTOR_ENC_KEY`).
Первый ключ перечня оборачивает каждый новый секрет, все ключи перечня открывают записанное.

Этого достаточно, чтобы **поставить** новый ключ без простоя, но недостаточно, чтобы **снять**
прежний: прежний ключ открывает каждый секрет, обёрнутый им, и перечень без него отдаёт `503`
(`second factor temporarily unavailable`) каждому такому человеку. Снять прежний ключ можно только
после того, как каждый уже записанный секрет перенесён под новый. Это делает команда
`kaname second-factor-key rewrap`.

## Что делает команда

Команда проходит все строки второго фактора — подтверждённые и незавершённые заведения — и каждый
секрет, обёрнутый не первым ключом перечня, оборачивает первым.

- **Секрет не меняется.** Меняется только обёртка: приложение-аутентификатор человека даёт те же
  коды, последний принятый код остаётся принятым, заведение не продлевается.
- **Служба работает во время прохода.** Каждая строка меняется отдельно и только если её значение
  не сменилось с момента чтения. Человек, заново заводящий или снимающий фактор во время прохода,
  не теряет своего действия: новое значение не перезаписывается прежним, снятая строка не
  возвращается.
- **Обрыв посреди безопасен.** Каждая строка в любой момент обёрнута либо первым ключом, либо
  прежним, который ещё стоит в перечне, — то есть читаема службой. Повтор команды продолжает.
- **Повтор ничего не пишет**, если всё уже под первым ключом.

Команда идёт той же настройкой, что служба, — та же база, тот же перечень, та же посадка. Запускать
её удобно в поде службы:

```bash
kubectl -n <namespace> exec deploy/<деплой kaname> -- kaname second-factor-key rewrap
```

Исход — одна строка со счётами:

```
second-factor-key rewrap keys=2 rows=1250 rewrapped=1250 current=0 unreadable=0 vanished=0 unsettled=0 outcome=done
```

| поле | что значит |
|---|---|
| `keys` | ключей в перечне |
| `rows` | строк второго фактора, увиденных проходом |
| `rewrapped` | перенесено под первый ключ этим проходом |
| `current` | уже были под первым ключом |
| `unreadable` | не открываются **ни одним** ключом перечня — не тронуты |
| `vanished` | человек снял фактор, пока проход держал его строку |
| `unsettled` | строку меняли перед каждой попыткой замены — повторите команду |

| код | `outcome` | что делать |
|---|---|---|
| `0` | `done` | каждый секрет под первым ключом |
| `1` | `partial` | не всё переехало: есть `unreadable` или `unsettled`. Прежние ключи **не снимать** |
| `3` | `not-run` или отказ до прохода | проход не доведён (база недоступна, отказала посреди, команда остановлена) либо настройка не принята. Перенесённое зафиксировано, повтор безопасен |

## Порядок смены ключа

1. **Порождите новый ключ** — 32 случайных байта в hex (64 знака), например `openssl rand -hex 32`.
2. **Поставьте его первым**, прежний оставьте следом: значение `НОВЫЙ,ПРЕЖНИЙ`. Выкатите и
   дождитесь, пока **каждая** реплика перезапустится с новым перечнем: при старте служба пишет в
   журнал `second-factor wrapping keys declared` с полем `keys`, равным `2`. Пока хоть одна
   реплика работает со старым перечнем, она оборачивает новые заведения прежним ключом.
3. **Переоберните записанное**: `kaname second-factor-key rewrap` → `outcome=done`.
4. **Подтвердите**: повторите команду с тем же перечнем. Повтор обязан напечатать `rewrapped=0` и
   `outcome=done` — ни одна реплика не обернула новое заведение прежним ключом после прохода.
   `rewrapped` больше нуля — какая-то реплика ещё работает со старым перечнем: вернитесь к шагу 2.
5. **Снимите прежний ключ** из перечня: значение `НОВЫЙ`. Выкатите.
6. **Проверьте без прежнего ключа**: команда с перечнем из одного нового ключа печатает `keys=1`,
   `unreadable=0`, `outcome=done` — каждый секрет открывается новым ключом.

Утёкший ключ проходит тот же порядок, и без промедления: после шагов 3–4 в базе не остаётся ни одного
секрета, обёрнутого им. Копии базы, снятые раньше, он открывает по-прежнему — этого переобёртка не
меняет.

## Если `unreadable` больше нуля

Такие секреты не открывает ни один ключ перечня команды, а значит — и служба с тем же перечнем.
Команда их не трогает.

- **Ключ снят раньше времени** (шаг 5 до шага 4): верните его в перечень следом за новым, выкатите и
  повторите с шага 3. Секреты не пострадали — команда не пишет того, чего не открыла.
- **Перечень команды не тот, что у службы**: команда судит своим перечнем. Запускайте её в поде
  службы либо с той же настройкой.
- **Ключа, которым секрет обёрнут, нет нигде**: секрет потерян, и его владелец уже получает `503` на
  предъявлении кода. Владельцу нужен сброс второго фактора администратором облака
  ([`UserService.ResetSecondFactor`](/api/user#reset-second-factor)) и новое заведение.

## Чего команда не делает

- Не меняет **ключ обёртки приватной половины подписного ключа** (`authn.jwks-encryption-key-hex`):
  это другой перечень и другой предмет. Ключница переезжает на новый ключ обёртки сама — по мере
  того как порождает ключи по сроку и снимает выведенные.
- Не порождает ключей и не правит перечень: перечень — настройка посадки, его меняет тот, кто её
  выкатывает.
- Не ставит срока на весь проход: его длительность пропорциональна числу людей с фактором.
  Ограничено каждое обращение к базе — десятью секундами.
