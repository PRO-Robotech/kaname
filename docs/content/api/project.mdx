# Project

**Project** — среднеуровневый контейнер внутри аккаунта ([Account](/api/account)). Это единица
изоляции рабочих нагрузок: именно к проекту привязываются ресурсы других сервисов —
VPC-сети и подсети, вычислительные инстансы, балансировщики. Проект группирует связанные ресурсы,
задаёт границу для квот и (главное) — **уровень выдачи прав**: роль можно привязать на конкретный
проект, ограничив доступ его содержимым.

Имя проекта уникально в пределах аккаунта (`(accountId, name)` — UNIQUE). Проект всегда
принадлежит ровно одному аккаунту.

## Методы

`ProjectService` — стандартный CRUD (`Create`/`Update`/`Delete` async → `Operation`;
`Get`/`List` sync) + журнал операций.

### Get — получить проект

<ApiOperation method="GET" endpoint="/iam/v1/projects/{project_id}">

Возвращает проект по идентификатору. Требует `v_get`.

<CodeBlock language="json">
  {dedent`
    {
      "id": "prj7mfpj2my52k5a06kg",
      "accountId": "acc2bkd71802av7dywa8",
      "name": "web-prod",
      "createdAt": "2026-06-24T10:05:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### List — список проектов аккаунта

<ApiOperation method="GET" endpoint="/iam/v1/projects">

Возвращает проекты аккаунта, **видимые вызывающему** (default-deny через фильтр страницы, не 403):
handler оставляет только те проекты, которые вызывающий вправе прочитать одиночным `Get`
(отношение `v_get`). Обязателен `accountId`; поддерживает `filter` по `name`.

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/iam/v1/projects?accountId=acc2bkd71802av7dywa8&pageSize=50' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

</ApiOperation>

### Create — создать проект

<ApiOperation method="POST" endpoint="/iam/v1/projects" async>

Создаёт проект в аккаунте. Требует `editor` на аккаунте. Асинхронно (`response: Project`).

<CodeBlock language="bash">
  {dedent`
    curl -X POST 'http://localhost:18080/iam/v1/projects' \\
      -H 'Authorization: Bearer <JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "accountId": "acc2bkd71802av7dywa8", "name": "web-prod" }'
  `}
</CodeBlock>

</ApiOperation>

### Update — изменить проект

<ApiOperation method="PATCH" endpoint="/iam/v1/projects/{project_id}" async>

Меняет `name` / `description` / `labels` по `updateMask`. **`accountId` не меняется** через
Update (задан при Create). Требует `v_update`. Асинхронно.

<CodeBlock language="bash">
  {dedent`
    curl -X PATCH 'http://localhost:18080/iam/v1/projects/prj7mfpj2my52k5a06kg' \\
      -H 'Authorization: Bearer <JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "updateMask": "labels", "labels": { "tier": "frontend" } }'
  `}
</CodeBlock>

</ApiOperation>

### Delete — удалить проект

<ApiOperation method="DELETE" endpoint="/iam/v1/projects/{project_id}" async>

Удаляет проект. Требует `v_delete`. Асинхронно. **Непустой проект не удаляется** — см. ниже.

</ApiOperation>

:::danger Непустой проект не удаляется — отказ приходит в операции и называет, что удерживает
Удаление проекта отвергается, пока служба доступа числит в нём хотя бы один ресурс.
Счёт приходит к ней от сервисов-владельцев и обновляется **не мгновенно**: ресурс,
созданный секунду назад, может ещё не числиться, а снятый — числиться ещё некоторое
время. Поэтому отказ есть **защита от штатной ошибки**, а не гарантия целостности:
гарантию даёт только владелец ресурса у себя. Порядок, при котором потерь не бывает,
прежний — снимайте ресурсы до проекта.

Перечень в отказе называет **зарегистрированные объекты**, а не выполненные вами
действия. Один созданный ресурс может числиться **несколькими** объектами разных видов:
служебные объекты, которые владелец заводит вместе с ним, регистрируются наравне с ним
самим. Поэтому снятие одного ресурса убирает из перечня и те виды, которых вы не
создавали по отдельности, — перечень отвечает на вопрос «что ещё числится», а не
«сколько раз вы нажали создать».

**Как выглядит отказ.** Удерживают два рода детей: ресурсы других сервисов,
зарегистрированные в проекте их владельцами (сети, машины, тома, балансировщики,
реестры), и проектные пользовательские роли. Запрос принимается (`200` с конвертом
операции — синхронной полосы у этого отказа нет), а операция завершается с ошибкой:

<CodeBlock language="json">
  {dedent`
    {
      "done": true,
      "error": {
        "code": 9,
        "message": "Project prj7mfpj2my52k5a06kg is not empty (compute.instance: 1, iam.role: 2, vpc.network: 3)",
        "details": [ { "reason": "REFERENCE_IN_USE", "domain": "iam.kaname.cloud" } ]
      }
    }
  `}
</CodeBlock>

| | |
|---|---|
| код | `FAILED_PRECONDITION` (9) |
| текст | `Project <id> is not empty (<вид>: <число>, …)` — виды в порядке имени; печатаются **виды и числа**, никогда идентификаторы дочерних; вид с нулём не печатается |
| признак полосы | `ErrorInfo.reason = REFERENCE_IN_USE` — тот же, что у всякого отказа «на ресурс ещё ссылаются»; следующий шаг — освободить ссылки |
| имя вида | точечное имя строки каталога (`vpc.network`, `compute.instance`, `storage.volumes`) — той же формой вид назван в ответе `GET /iam/v1/permissionCatalog`; проектная роль — `iam.role` |

**Что делать дальше:** снимите названные ресурсы их собственными глаголами удаления
(адресация по `id` от проекта не зависит) и проектные роли — `DELETE /iam/v1/roles/{id}`, —
затем повторите тот же запрос. Пустой проект удаляется: выдачи, ограниченные проектом,
снимаются в той же транзакции, что и его строка.

Снятый вид ресурса (в ответе каталога прав — `retiredResources`) в перечне остаётся тем же
именем: перечень называет то, что числится. Строку такого вида снимает владелец ресурса;
если в отказе стоит вид, который вам удалить нечем, обратитесь к оператору.

Механизм заведён в рамках [`#1231`](https://github.com/PRO-Robotech/kacho/issues/1231);
открытым по этой задаче остаётся сквозное наблюдение живого ресурса другого домена через
край платформы — оно живёт в наборе платформы, а не службы.
:::
