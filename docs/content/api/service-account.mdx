# ServiceAccount

**ServiceAccount** — машинный (non-human) субъект платформы: идентичность для рабочих нагрузок,
CI-пайплайнов, интеграций и автоматизации. Там, где User представляет человека, ServiceAccount
представляет программу. Ему выдают роли ровно так же, как пользователю (через AccessBinding), но
аутентифицируется он не логином, а **OAuth 2.0-ключом** (см. [Токены доступа](/api/tokens)).

Сервис-аккаунт принадлежит аккаунту; опционально может быть привязан к проекту (`projectId`).
Состояние `enabled` позволяет временно отключить возможность аутентификации без удаления —
через отдельные действия `:disable` / `:enable` (см. ниже), не через `Update`.

## Методы

`ServiceAccountService` — стандартный CRUD (`Create`/`Update`/`Delete` async; `Get`/`List` sync),
два явных действия `:disable` / `:enable` + журнал операций. Выпуск ключей — отдельный сервис
`SAKeyService` (см. [Токены доступа](/api/tokens)).

### Get — получить сервис-аккаунт

<ApiOperation method="GET" endpoint="/iam/v1/serviceAccounts/{service_account_id}">

Возвращает сервис-аккаунт по идентификатору. Требует `v_get`.

<CodeBlock language="json">
  {dedent`
    {
      "id": "svavn8sraky9vgh0ygc8",
      "accountId": "acc2bkd71802av7dywa8",
      "name": "ci-builder",
      "enabled": true,
      "createdAt": "2026-06-24T10:10:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### List — список сервис-аккаунтов

<ApiOperation method="GET" endpoint="/iam/v1/serviceAccounts">

Возвращает сервис-аккаунты аккаунта, **видимые вызывающему** (default-deny через scope-filter,
не 403). Обязателен `accountId`; поддерживает `filter` по `name`.

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/iam/v1/serviceAccounts?accountId=acc2bkd71802av7dywa8&pageSize=50' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

</ApiOperation>

### Create — создать сервис-аккаунт

<ApiOperation method="POST" endpoint="/iam/v1/serviceAccounts" async>

Создаёт сервис-аккаунт в аккаунте. Требует `editor` на аккаунте. Асинхронно
(`response: ServiceAccount`).

<CodeBlock language="bash">
  {dedent`
    curl -X POST 'http://localhost:18080/iam/v1/serviceAccounts' \\
      -H 'Authorization: Bearer <JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "accountId": "acc2bkd71802av7dywa8", "name": "ci-builder" }'
  `}
</CodeBlock>

</ApiOperation>

### Update — изменить сервис-аккаунт

<ApiOperation method="PATCH" endpoint="/iam/v1/serviceAccounts/{service_account_id}" async>

Меняет `name` / `description` / `labels` по `updateMask`. `accountId` immutable. Требует
`v_update`. Асинхронно.

`enabled` в `updateMask` **не принимается**, и такого поля в запросе нет: пустая маска по
конвенции означает полную замену объекта, а `bool` в proto3 неотличим от неприсланного —
поэтому вариант «ещё одно поле маски» позволил бы клиенту отключить учётку, просто его не
заполнив. Отключение — отдельное действие, см. ниже.

<CodeBlock language="bash">
  {dedent`
    curl -X PATCH 'http://localhost:18080/iam/v1/serviceAccounts/svavn8sraky9vgh0ygc8' \\
      -H 'Authorization: Bearer <JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "updateMask": "description", "description": "CI builder (main pipeline)" }'
  `}
</CodeBlock>

</ApiOperation>

### Disable — отключить аутентификацию

<ApiOperation method="POST" endpoint="/iam/v1/serviceAccounts/{service_account_id}:disable" async>

Учётка перестаёт получать новые токены и удостоверения: закрываются ВСЕ пути выдачи — token-hook
(`client_credentials` и федеративная ассерция), `SAKeyService.Issue`, docker-token (по базовому
токену доступа). Уже выданные access-токены **не инвалидируются** — они доживают свой срок.

Действие, а не поле маски: у действия нет маски, которую можно забыть. **Идемпотентно** —
отключение уже отключённой учётки успешно (предмет запроса — состояние, а не переход).
Требует `v_update` — то же отношение и на том же объекте, что `Update`.

Дополнительно объявлен порог повышенной аутентификации (`acr=2`): один вызов решает за ВЕСЬ
принципал тот вопрос, который отзыв ключа решает за один ключ. Порог **интерактивный** —
машинный принципал от него освобождён платформенным правилом, поэтому служебной учётке с
`v_update` он ничего не добавляет и ничего не запрещает.

Асинхронно, и **порядок между двумя одновременными запросами не гарантирован**: `Enable`,
отправленный раньше, может примениться позже `Disable`. Состояние следует перечитывать через
`Get`, а не выводить из порядка отправки.

В журнал пишется событие `iam.service_account.disabled` (кто, кого, когда).

<CodeBlock language="bash">
  {dedent`
    curl -X POST 'http://localhost:18080/iam/v1/serviceAccounts/svavn8sraky9vgh0ygc8:disable' \\
      -H 'Authorization: Bearer <JWT c acr=2>' \\
      -H 'Content-Type: application/json' -d '{}'
  `}
</CodeBlock>

</ApiOperation>

### Enable — вернуть аутентификацию

<ApiOperation method="POST" endpoint="/iam/v1/serviceAccounts/{service_account_id}:enable" async>

Обратное действие: учётка снова получает токены и ключи. Та же форма — идемпотентно, требует
`v_update` + `acr=2`, асинхронно, событие `iam.service_account.enabled`.

</ApiOperation>

### Delete — удалить сервис-аккаунт

<ApiOperation method="DELETE" endpoint="/iam/v1/serviceAccounts/{service_account_id}" async>

Удаляет сервис-аккаунт. Если на него ссылается активный AccessBinding — удаление блокируется
`FAILED_PRECONDITION` (сначала снять привязки). Требует `v_delete`. Асинхронно.

</ApiOperation>

### ListOperations — операции над сервис-аккаунтом

<ApiOperation method="GET" endpoint="/iam/v1/serviceAccounts/{service_account_id}/operations">

Возвращает операции над сервис-аккаунтом. Sync, курсорная пагинация. Требует `v_list`.

</ApiOperation>

:::tip Как SA получает токен
Сервис-аккаунт аутентифицируется через OAuth 2.0-ключ (`SAKeyService.Issue`) и Ory Hydra:
рабочая нагрузка подписывает `client_assertion` приватным ключом и обменивает его в
`/oauth2/token` на kacho-JWT. Детали и федерация — [Токены доступа](/api/tokens).
:::
