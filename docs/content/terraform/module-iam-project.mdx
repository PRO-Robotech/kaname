# Модуль `iam-project`

Модуль заводит проект вместе с группами и служебными учётками, которые в нём работают, —
типовую единицу, которую создают целиком при появлении новой команды или контура.

## Использование

```hcl
module "prod" {
  source = "github.com/PRO-Robotech/kacho//terraform/modules/iam-project"

  account_id  = var.account_id
  name        = "production"
  description = "боевой контур"
  labels      = { env = "prod" }

  groups = {
    "prod-admins"   = "администраторы контура"
    "prod-viewers"  = "чтение без права правки"
  }

  service_accounts = {
    "ci-deployer" = "учётка конвейера выкатки"
  }
}
```

## Переменные

| Имя | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `account_id` | `string` | — | Аккаунт-владелец. |
| `name` | `string` | — | Имя проекта в пределах аккаунта. |
| `description` | `string` | `""` | Описание проекта. |
| `labels` | `map(string)` | `{}` | Метки на все ресурсы модуля. |
| `groups` | `map(string)` | `{}` | Группы: ключ — имя, значение — описание. |
| `service_accounts` | `map(string)` | `{}` | Служебные учётки: ключ — имя, значение — описание. |

## Выходы

| Имя | Что это |
|---|---|
| `project_id` | Идентификатор проекта — им адресуются все ресурсы облака. |
| `group_ids` | Идентификаторы групп по их именам. |
| `service_account_ids` | Идентификаторы служебных учёток по их именам. |

## Почему группы и учётки заводятся в аккаунте, а не в проекте

Так устроен контракт: и группа, и служебная учётка принимают `account_id`, поля проекта у
них нет. Практический смысл тот же — одна и та же группа обычно получает права в нескольких
проектах, и заведение её «внутри проекта» плодило бы одноимённые группы, состав которых
разъедется.

**Сужение до проекта делается выдачей прав**, а не местом заведения.

## Права — группе, а не перечислению

Модуль принимает `groups`, а не список людей, намеренно. Право, которое получает больше
одного принципала или чей состав может измениться, выдаётся группе; люди и служебные учётки
в неё добавляются. Снять одного из группы — одна запись членства; снять одного из
перечисления — снятие прав по всем объектам роли.

## Порядок сноса

Служебные учётки и группы не ссылаются на проект, поэтому Terraform волен снести их в любом
порядке. Проект при этом удалится последним, только если в нём не осталось пользовательских
ролей: край защищает эту ссылку на уровне хранилища и вернёт отказ с названной причиной.

## Чем проверяется сам модуль

У модуля есть пробы: `tests/wiring.tftest.hcl`, гоняются командой `tofu test` из каталога
модуля. Провайдер в них подменён (`mock_provider`), то есть край не участвует — падение
означает ошибку в модуле, а не состояние стенда.

Пробы закрепляют две вещи: **связывание** (что на что ссылается, откуда берутся имена, что
доезжает до ресурса) и **отвержение** негодного входа. Второе не менее важно первого: без
отрицаний положительные пробы зеленели бы и на модуле, принимающем что угодно.

Конвейер требует пробы от КАЖДОГО модуля и падает на модуле без них.
