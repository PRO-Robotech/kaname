## Решения, которые вносит приёмка

1. **SUAD1** (Р1): четвёртый способ `webauthn` у того же глагола `step-up`; форма по способу — лишнее поле отвергается с именем поля.
2. **SUAD2** (Р2): новый глагол `step-up/access-key/begin`. Испытание привязано к записи сессии, живое у сессии одно, новая выдача сменяет прежнее. Срок испытания — `ChallengeTTL`; выдача попыткой не считается.
3. **SUAD3** (Р3): порядок предъявления: форма → сессия → частота → сгорание → строка ключа этого человека → сверка → предъявление одним исходом. Все суждённые отказы — один 401.
4. **SUAD4** (Р4): уровень считается правилом Ф11 Р2 по флагам ЭТОГО утверждения; ответ прежней формы.
5. **SUAD5** (Р5): новый отказ состояния `ACCESS_KEY_NOT_REGISTERED`.
6. **SUAD6** (Р6): новые ключи чтения состояния: `totp.lastUsedAt`, `backupCodes.issuedAt`, `backupCodes.lastUsedAt`, `accessKeys.available`, `stepUpMethods`. Отсутствие выражается отсутствием ключа.
7. **SUAD7** (Р7): «ключи выключены» выводится из пустого перечня происхождений. Новый отказ `ACCESS_KEYS_DISABLED` у трёх выдач испытания.
8. **SUAD8** (Р8): один счёт попыток на все способы; величины берутся из профиля.
9. **SUAD9** (Р10): журнал и клетки наблюдаемости для `webauthn`.
10. **SUAD10** (Р11): новый путь на слушателе формы; впервые достижим уровень «3» внутри сессии, выданной паролем.

## Вернуть в приёмку

- **M1 (средняя, аудитор поверхности).** SUA Р3: в таблице отказов 401 нет двух причин — «счётчик подписи не вырос» и «сдвиг счётчика проигран». В Р10 нет клетки счётчика. В §3.2 нет близнеца SUA-03, в котором единственный отличающий факт — счётчик ≤ записанного. В §8 п.1 и п.2 нет пробы на это. Это **отсутствующее наблюдаемое поведение** (`fa-b2`), поэтому место ему в приёмке. Правка — редакция 3 SUA. Она меняет отпечаток, и этот разбор переводится на новый отпечаток **только по дельте** (`fa-b1`).
