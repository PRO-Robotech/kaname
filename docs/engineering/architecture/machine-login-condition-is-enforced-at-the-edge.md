# Вход ВНУТРЬ машины: требование усиленного входа исполняет край

Решение по задаче #2056. Предмет — два отношения модели прав
(`proto/kaname/cloud/iam/v1/fga_model.fga`, тип `compute_instance`):

```
define ssh:     [user with mfa_fresh, service_account] or admin
define console: [user with mfa_fresh] or admin
```

Левая часть объявляет требование свежего второго фактора. Правая его **обходит**:
распорядителю ресурса условие не нужно. Этого никто не решал — ветвь `or admin`
приехала формой соседних отношений (`viewer` / `editor` / `admin`), где условия
нет и быть не должно.

## Почему различие существенно

`viewer` / `editor` / `admin` — про **управление** ресурсом: создать, изменить,
удалить. Каждое такое действие оставляет след в журнале операций платформы и
обратимо её же средствами.

`ssh` и `console` — про вход **внутрь** машины. За тем, что происходит после
входа, не наблюдает ни одна проверка платформы: она отдала консоль и больше не
участвует. Требование к такому переходу не выводится из требования к управлению
машиной и обязано быть решено отдельно.

## Замер: почему это укрепление ВПЕРЁД, а не действующий дефект

Обе стороны, ревизия — линия `integration/standalone-iam`:

| вопрос | предикат | ответ |
|---|---|---|
| записей каталога, требующих `ssh` | разбор встроенной копии каталога прав | **0** |
| записей каталога, требующих `console` | то же | **0** |
| RPC входа в машину в контрактах | `git grep -niE 'rpc +(Ssh\|Console\|GetSerialConsole)' -- proto` | **0** |

Читателя нет ни одного: вердикт по этим отношениям сегодня не спрашивает никто,
и эксплуатируемого состояния не существует. Но форма уже написана, и в день,
когда вход в машину появится, она начнёт действовать **в том виде, в каком
лежит**.

## РЕШЕНИЕ: энфорсером объявлен КРАЙ

Задача называла два исхода. Первый — вернуть условие администратору внутри
модели — **невыразим средствами языка модели**, и это замер, а не мнение: условие
приписывается ТОЛЬКО прямому присвоению (`[тип with условие]`), вычисляемой ветви
(`or admin`) его приписать нечем. Форм `or … with …` в каноническом файле — **0**,
контрпримера в дереве нет.

Обходной путь «завести отдельное отношение `admin_with_mfa`» отвергнут: выдать его
было бы **нечем**. Роль отображается в ярусы `viewer` / `editor` / `admin`
(`authzmap.PermissionsToRelations`), правило роли даёт только глаголы `v_*`
(`authzmap.GrantedVerbs`); пути, которым такой кортеж попал бы в хранилище, не
существует. Проверка против него отвечала бы «нет» всем и всегда, оставаясь на вид
полноценным гейтом, — тот же класс, по которому уже снято `billing_admin`
(`relations-without-readers-withdrawn.md`).

Остаётся второй исход, и он принят:

> **Запись каталога прав всякого RPC, требующего отношения `ssh` либо `console`,
> обязана нести `required_acr_min`. Край объявлен авторитетным энфорсером полосы
> входа в машину.**

Механизм не изобретается: `required_acr_min` уже несут **323** записи каталога из
350, то есть это рабочая, а не заводимая под этот случай ручка.

## Что из этого следует для того, кто заведёт вход в машину

1. RPC входа получает запись каталога с `required_relation: ssh` (или `console`)
   **и** непустым `required_acr_min`;
2. ветвь `or admin` в модели при этом **остаётся** — она отвечает на вопрос «кому
   вообще принадлежит машина», а требование свежести фактора отвечает на другой
   вопрос и живёт на крае;
3. проба на само отношение заводится **вместе с первым читателем**, не раньше:
   сегодня её нечем позвать.

## Чем держится

Гейтом `services/iam/internal/authzmap`
`TestConditionBypassedByAnArmNeedsTheEdgeEnforcer`. Он **молчит, пока читателя
нет**, и краснеет в тот момент, когда запись каталога начинает требовать
обходимого отношения без величины усиленного входа, — то есть послабление
истекает от появления предмета, а не от чьей-то памяти.

Гейт печатает объём осмотренного (типов модели, объявлений, из них с условием, из
них с обходимым условием, записей каталога, из них читающих обходимое отношение) и
отказывает на пустом разборе. Его способность упасть доказана инъекцией —
`condition_bypass_injection_test.go`, пять проб, обе стороны по каждой оси,
включая читателя С величиной (молчание) и разбор, судящий узлы объявления, а не
слова `or` и `with` в прозе.

**Чего гейт не ловит** (названо, чтобы на него не сослались шире предмета): он не
судит, верна ли сама величина `required_acr_min`, и не видит энфорса в хендлере —
пара, решение по которой принимает сервис, каталогом не выражается by
construction.
