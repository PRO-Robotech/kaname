## 1. Предмет

На типе `iam_role` объявлено отношение `v_get`, и **читателя у него нет ни
одного**. Право, выданное по нему, не даёт ничего: ни один путь запроса его не
спрашивает, ни одна запись каталога прав его не называет, а единичное чтение
роли энфорсится **другим** предикатом — тем же, которым фильтруется страница.

Это третья поверхность класса «право выдаётся и не даёт ничего» (родня `#1825`,
`#1827`): там были строка права и класс правила, здесь — **отношение ТИПА**.
Поэтому закрыть его правкой правила нельзя: подстановочное правило
`iam.role.admin` (`classes: ["*"]`) разворачивается в набор ТИПА и продолжает
называть снятый класс by construction.

**Чем это видно арендатору.** Превью роли (`effective_verbs`) с `#1994`/`#1816`
читает живые строки каталога, то есть набор глаголов ТИПА; держатель
`iam.role.admin` видит там `get`. Редактор ролей строит выпадающий список из
`CatalogResource.verbs` — контракт говорит это дословно
(`permission_catalog_service.proto`: «ЭТО — ИСТОЧНИК ВЫПАДАЮЩЕГО СПИСКА редактора
ролей, а не `closed_verbs`»), — и у `iam.role` сегодня там `get`. Обе поверхности
обещают то, чего не исполняет ни один путь, — ровно та находка, которую ban #18
называет отдельно: **возможность объявлена и неисполнима**.

## 3. РЕШЕНИЕ: снять отношение с типа. Второй исход отвергнут

Задача называет два исхода, и оба правят контракт чтения. Выбран **второй**.

### 3.1. Почему не «дать читателя»

Перевести единичное чтение роли на `v_get` значит сломать объявленное свойство:
страница и единичное чтение решают ОДНИМ предикатом —

```
{role : Get(role) успешен} == {role : role ∈ List}
```

**Держится оно прежде всего ПОСТРОЕНИЕМ**: обе поверхности зовут один резолвер —
`role/get.go:110` и `role/list.go:326`, обе `resolveVisibleRoleIDs`, — поэтому
разойтись не могут by construction. Сверх построения его держит проба, зовущая
**оба** use-case, — `TestGetRole_D45_ReadEnforceParity_GetSetEqualsListSet`
(уточнение круга 3; перечень держателей — GWT-6).

Круг 1 называл держателем `TestVisibleSet_RoleKeepsTheUnionItsOwnGetEnforces`.
**Неверно:** её тело — один поддельный проверяльщик, один вызов `VisibleSet` и
одно утверждение; `Get` в ней не зовётся ни разу. Она держит ОДНУ сторону
(страница включает роль при гранте `v_list`), а не паритет. Заголовок шире тела
(`testing.md` §«Гейт на класс» п. 6), и опираться на неё как на держателя паритета
нельзя.

Довод против второго исхода от этого не ослаб, а укрепился: разводить два
предиката там, где сегодня один вызов, — значит заводить второе место об одном
вопросе, расходящееся молча. Цена для арендатора наблюдаема: роль, видимая в
перечне, перестала бы открываться поимённо, и «перечень врёт» было бы
единственным, что он увидит.

### 3.2. Почему «снять» — и что снятие НЕ отнимает

Снятие не отнимает **доступа**: у отношения нет читателя, значит по нему ничего
не предоставлялось никогда. Снимается не право, а **обещание права** — и вместе
с ним сужается словарь предлагаемых глаголов (§2.4), что и есть цена.

Проверка пятью вопросами (ban #18):

| вопрос | ответ |
|---|---|
| **благо продукта** | выигрыш не в объёме работы: снимается утверждение, которое продукт делает и не исполняет |
| **конкурентоспособность** | предсказуемость контракта: превью роли и словарь редактора перестают называть глагол, которого не бывает |
| **перспективность** | **обратимо**: снятие помечает строку (`RetireVerb`), оживление — объявление того же глагола в манифесте, и `UpsertVerb` поднимает **ту же** строку (`ON CONFLICT … DO UPDATE SET retired_at=NULL, live=true`). Внешне-адресуемая координата не трогается (ban #15), миграции данных арендатора нет |
| **безопасность** | поверхность **сужается**: перестают материализоваться кортежи, которых не читает никто. Ни один путь решения о доступе не меняется |
| **производственность** | режима «только для стенда» нет; отложенного нет; снятие идёт тем же путём, которым каталог принимает всякое изменение манифеста |

## 4. ЦЕНА СНЯТИЯ — где премиса задачи опровергнута, а где подтверждена ДРУГИМ доводом

Тело `#1922` называет снятие «правкой канонической модели, раздела `resources`
манифеста и посева `catalog_verb`, **плюс новая миграция по живым строкам**», а
комментарий линии добавляет: «применённую править нельзя, ban #5».

### 4.1. ОПРОВЕРГНУТО: отзыв в рантайме — данные, а не миграция

Каталог модуля живёт данными (эпик `#1027`), и у снятия глагола есть
производитель, исполняющийся **на подъёме**:

```sh
# apply.go:184  RetireVerb(ctx, v catalog.VerbRow, reason string) (bool, error)
# apply.go:549  retired, terr := w.RetireVerb(ctx, v, reason)
```

План собирает корзину снятого из разности «что в базе» против «что объявлено
манифестом» (`modulecatalog/plan.go:180-192`, ветвь `gone.Verbs`); применитель
зовётся композиционным корнем до подъёма слушателей
(`cmd/kaname/serve.go:359`, `applyDeliveredManifests`, отказ фатален), и порядок

SET retired_at = now(), live = false, retired_reason = $4 … AND live`
(`internal/repo/kaname/pg/catalog_writer.go:339`): строка **помечается**, а не
удаляется.

### 4.2. ИСПРАВЛЕНО: механизм ключа круг 1 описал неверно ДВАЖДЫ

```sql
ADD CONSTRAINT role_rule_ref_verb_fk
  FOREIGN KEY (module, resource, verb, live)
  REFERENCES kaname.catalog_verb(module, resource, verb, live) DEFERRABLE;
```
(`internal/migrations/0001_initial.sql:5530`)

- `ON DELETE RESTRICT` у этого ключа **нет вовсе** — круг 1 называл действие,
  которого не существует;
- `live` входит в ключ **с обеих сторон**, поэтому пометка снятой **уничтожает**
  референт `('iam','role','get', true)`, а не сохраняет его. Вывод круга 1
  («строка помечается снятой, ПОЭТОМУ ключ держится») неверен как вывод.

**Ключ держится по двум другим причинам, и обе про ДАННЫЕ:** ни одна системная
строка `role_rule_ref` этот глагол не называет (§2.6, четыре строки, `get` среди
них нет), а арендаторские снимает `ResettleTenantProjections` (ветвь
`stale_verb`) **до** снятия. Системные она не трогает намеренно:
`catalogStaleRuleRefPredicate` объясняет, что манифест, снимающий то, что его же
роль называет, противоречит сам себе, и это обязано быть отвергнуто ключом.

### 4.3. РЕШЕНИЕ по паритету посева: НОВОЙ МИГРАЦИИ НЕТ, гейт дерева принимает асимметрию стража старта

`internal/check` `TestIAMCT114_CatalogSeedMatchesTheLiteral` читает **ТЕКСТ**
посева и требует ТОЧНОГО равенства множеств с литералом, выведенным из манифеста:

```sh
go test -count=1 -short -v ./internal/check/ -run CatalogSeedMatchesTheLiteral
# осмотрено: литерал — модулей 6, ресурсов 27, пообъектных глаголов 109;
# прочитано строк — модуля 6, ресурса 30, глагола 135; … снятых ресурсов 3
```

Гейт **даёт вердикт в этом репозитории** (не пропуск) и читает **один** файл
(`catalogMigrationPath`), хотя миграций 11; поздние десять строк каталога не
трогают (`grep -E "(INSERT INTO|UPDATE|DELETE FROM) kaname.catalog_"` по ним → 0).
Снятие глагола из манифеста делает его красным: строка 3300 `0001_initial.sql`
продолжает сеять `('iam','role','get', NULL, NULL, true, true)`.

Круг 2 оставил выбор исхода открытым. **Круг 4 выбирает ОДИН: гейт дерева
принимает ту же асимметрию, которую страж старта уже принял решением `#1861`.**

#### Почему этот исход — прецедент, а не послабление

Страж старта `internal/apps/kaname/seed/catalog_parity.go` решал **ту же задачу** и
записал решение шапкой: «Литерал — ВЕРХНЯЯ ГРАНИЦА, а не равенство (задача #1861).
Требуй страж ТОЧНОГО равенства — и снятие строки становится невозможным by
construction». Гейт дерева по-прежнему требует равенства, то есть в дереве **два
места об одном предмете, и верно то, которое уже решено**. Выровнять гейт по
решению — не ослабление ради зелёного, а снятие расхождения, при котором снятие
глагола невозможно в принципе.

**Свойство, которое гейт обязан держать после выравнивания:**

| множество | вердикт |
|---|---|
| объявлен литералом и посеян | норма |
| объявлен литералом и **не** посеян | **находка**, как сегодня: эту половину выравнивание не трогает |
| посеян живым и **не** объявлен литералом | **законно** и печатается отдельной строкой переписи «посеяно, снимается применителем на подъёме: N» |

#### Почему «посеяно и не объявлено» законно — механизм, а не допущение

Применитель каталога исполняется композиционным корнем до подъёма слушателей
(`cmd/kaname/serve.go:359`), **одной пишущей транзакцией** (`RunInWriteTx`, замок
каталога первым оператором) и в ней делает по порядку
(`internal/apps/kaname/modulecatalog/apply.go:537-560`):

1. `Withdrawn(live, declared)` — живые строки, которых манифест не объявляет;
2. `ResettleTenantProjections` — переселяет в `role_grant_orphan` проекции
   **арендаторских** ролей, называющих снимаемое;
3. `RetireVerb` — помечает строку снятой.

Ключ `role_rule_ref_verb_fk` — `DEFERRABLE` без `INITIALLY DEFERRED`, то есть
проверяется сразу, и `live` входит в него с обеих сторон. Поэтому шаг 2 **до**
шага 3 — не порядок вкуса, а условие того, что шаг 3 вообще проходит: к моменту
пометки строк, ссылающихся на `('iam','role','get', true)`, в той же транзакции
уже нет. Системные роли глагол не называют (§2.6).

#### Отвергнутые исходы — с причиной, а не перечислением

- **новая миграция** `UPDATE … SET live=false`: обходит шаг 2. На стенде, где
  арендаторская роль называет `iam.role.get`, отказывает немедленно — ключ
  проверяется сразу. Такая роль выразима сегодня: арендаторская политика
  ограничивает только подстановки (`internal/domain/rule_policy.go`), а писатель
  кладёт глагол в строку как есть (`role_repo.go:1011`). Обходит и запись в
  `role_grant_orphan`. Вывод круга 3 получен чтением ключа и политики; на живой
  базе не прогонялся — и не нужен, потому что исход отвергнут;
- **поимённое послабление** в гейте: механизма нет — сверка множеств в
  `auditCatalogSeed` ведомости исключений не имеет, единственная ведомость пакета
  (`restrictDeferrableExempt`) относится к форме ключа. Причина послабления — текст
  применённой миграции — не уйдёт никогда, значит у него не было бы предиката
  снятия (`testing.md` §«Подпорка»);
- **отказ от снятия** противоречит §3 и из перечня исходов снят.

#### Цена выбранного исхода — названа

1. **текст посева навсегда несёт живую строку снятого глагола** (ban #5: применённое
   не правится); каждая свежая установка проходит одно снятие на первом подъёме.
   На свежей базе арендаторских ролей нет, шаг 2 переселяет ноль строк;
2. **гейт перестаёт краснеть на СЛУЧАЙНО посеянном лишнем глаголе.** Такой глагол
   тем же применителем снимается на подъёме — по решению `#1861` это безвредно, — а
   ненулевое N в переписи делает его видимым. Число печатается всегда, в том числе
   ноль: «ноль снимаемых» обязано быть отличимо от «не считали»;
3. гейт живёт в `internal/check` — правка чужого для этой волны каталога, и её
   реализация обязана назвать это при сборке.

Ban #5 не задет: применённая миграция не правится.

## 5. Приёмочные сценарии (Given-When-Then)

### GWT-1 — отношение не объявлено ни манифестом, ни моделью, и таблица с манифестом сходится

**Дано** дерево после изменения.
**Когда** читают объявление ресурса `role` в `manifest.yaml`, блок `type iam_role`
канонической модели и порождённую таблицу набора глаголов.
**Тогда** ни манифест, ни модель не называют `get`/`v_get`.
**И** набор `verbs` ресурса `role` в манифесте равен `[list, update, delete]` и
**совпадает** с записью `iam_role` в `internal/authzmap/tables_gen.go`.

Предикат по Go — прежний:

```sh
git grep -n "v_get" -- '*.go' ':!*_test.go' ':!pkg/api/*' | grep -i iam_role   # пусто
```

Предикат звена «манифест ↔ таблица» — машинный, потому что Go-предикат манифест
не читает, а держатель звена в этом клоне не исполним (§4.4). Скрипт сравнивает
множество `v_<verb>` ресурса `role` с множеством строки `"iam_role":` и отказывает
кодом 2, если не нашёл ровно одного ресурса либо ровно одной строки, — «ноль
найдено» не читается как «сошлось»:

```python
import re, sys, yaml
m = yaml.safe_load(open("manifest.yaml", encoding="utf-8"))
res = [r for r in m.get("resources", []) if r.get("name") == "role"]
if len(res) != 1: sys.exit(2)
mv = sorted("v_" + v for v in res[0].get("verbs", []))
line = [l for l in open("internal/authzmap/tables_gen.go", encoding="utf-8")
        if re.match(r'\s*"iam_role":', l)]
if len(line) != 1: sys.exit(2)
tv = sorted(re.findall(r'"(v_[a-z]+)"', line[0]))
sys.exit(0 if mv == tv else 1)
```

Доказан в обе стороны на `8985cd41` (копии входов — в песочнице автора, дерево не
правилось):

| мир | манифест | таблица | код |
|---|---|---|---:|
| сегодня | с `get` | с `v_get` | **0** |
| симуляция A круга 3 | с `get` | без `v_get` | **1** |
| манифест правлен, таблица нет | без `get` | с `v_get` | **1** |
| законный близнец — полный DoD | без `get` | без `v_get` | **0** |

Реализация переносит предикат в **пробу** — сверку `verbs` каждого ресурса
манифеста с порождённой таблицей (DoD п. 3); предикат выше — её однотиповая форма
и контроль её рождения.
