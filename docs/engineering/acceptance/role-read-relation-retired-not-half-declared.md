# Приёмка: отношение чтения роли СНИМАЕТСЯ, а не остаётся полуобъявленным

- **Статус:** DRAFT — ждёт круга `acceptance-reviewer`. Кода по §5 не писать до
  вердикта (ban #1). Автор вердикта себе не ставит.
- **Ревизия измерения:** `PRO-Robotech/kaname`, ветка `lane/w2-domain` от
  `origin/release/iam-closeout`, база `a18659d1`
- **Тип изменения:** снятие объявленной и неисполнимой возможности; наблюдаемо
  арендатору в превью роли. Контракта на проводе не ломает
- **Сервис:** `kaname`; затрагивает `manifest.yaml`, `proto/kaname/cloud/iam/v1/fga_model.fga`,
  `internal/authzmap` (порождаемое), строки `kaname.catalog_verb`
- **Задача:** `PRO-Robotech/kacho#1922`, п. 1 (пп. 2–3 закрыты `#2047`, перемерены
  дважды, предикат пуст)

---

## 1. Предмет

На типе `iam_role` объявлено отношение `v_get`, и **читателя у него нет ни
одного**. Право, выданное по нему, не даёт ничего: ни один путь запроса его не
спрашивает, ни одна запись каталога прав его не называет, а единичное чтение
роли энфорсится **другим** предикатом — тем же, которым фильтруется страница.

Это третья поверхность класса «право выдаётся и не даёт ничего» (родня `#1825`,
`#1827`): там были строка права и класс правила, здесь — **отношение ТИПА**.
Поэтому закрыть его правкой правила нельзя: подстановочное правило
`iam.role.admin` (`classes: ["*"]`) разворачивается в набор ТИПА и продолжает
называть снятый класс by construction.

**Чем это видно арендатору.** Превью роли (`effective_verbs`) с `#1994`/`#1816`
читает **живые строки каталога**, то есть набор глаголов ТИПА. Держатель
`iam.role.admin` видит в превью `get` — обещание, которое не исполняет ни один
путь. Это ровно та находка, которую ban #18 называет отдельно: **возможность
объявлена и неисполнима**.

| записей с `required_relation = v_get` во всём каталоге | **27** |

Путь чтения службы объявляет то же и объявляет ЯВНО —

предикат страницы `{v_get}`, у `iam_role` — `{viewer, v_list}`.

Читателя на пути запроса нет:

```sh
git grep -n "v_get" -- '*.go' ':!*_test.go' ':!pkg/api/*' | grep -i iam_role
# → internal/authzmap/tables_gen.go:43 — и только он
```

Единственное попадание — **порождённая** таблица набора глаголов типа, то есть
ПИСАТЕЛЬСКАЯ сторона: из неё эмитируются кортежи, которых не читает никто.

Кто называет ресурс `role` в манифесте (`manifest.yaml`, 19 ролей):

| роль | классы |
|---|---|
| `iam.role.admin` | `["*"]` — подстановка, разворачивается в набор типа |
| `iam.role.edit` | `[list, update]` |
| `iam.role.view` | `[list]` |

**Ни одна роль не называет `get` ПОИМЁННО.** Значит снятие затрагивает
единственный путь — разворот подстановки.

Референтов снятия в посеве нет:

```sh
grep -c "INSERT INTO kaname.role_rule_ref_verb" internal/migrations/0001_initial.sql   # → 0
```

## 3. РЕШЕНИЕ: снять отношение с типа. Второй исход отвергнут

Задача называет два исхода, и оба правят контракт чтения. Выбран **второй**.

### 3.1. Почему не «дать читателя»

Перевести единичное чтение роли на `v_get` значит сломать объявленное и
**закреплённое пробой** свойство: страница и единичное чтение решают ОДНИМ
предикатом —

```
{role : Get(role) успешен} == {role : role ∈ List}
```

Держатель — `internal/authzfilter/read_parity_test.go`,
`TestVisibleSet_RoleKeepsTheUnionItsOwnGetEnforces`; сам код объясняет, почему
так: обе поверхности зовут `role.resolveVisibleRoleIDs`, поэтому разойтись не
могут **by construction**, и грант по селектору роли (`v_list` без яруса) есть
объявленный контракт «видно в перечне», который `Get` чтит ровно так же.

Дать читателя — значит завести **второй** предикат об одном предмете и получить
ровно тот класс, который корпус ловит: два места об одном вопросе, расходящиеся
молча. Цена для арендатора наблюдаема: роль, видимая в перечне, перестала бы
открываться поимённо — и «перечень врёт» было бы единственным, что он увидит.

### 3.2. Почему «снять» — и что снятие НЕ отнимает

Снятие не отнимает **ничего**, и это измерено, а не предположено: у отношения
нет читателя, значит доступ по нему не предоставлялся никогда. Снимается не
право, а **обещание права**.

Проверка пятью вопросами (ban #18):

| вопрос | ответ |
|---|---|
| **благо продукта** | выигрыш не в объёме работы: снимается утверждение, которое продукт делает и не исполняет |
| **конкурентоспособность** | предсказуемость контракта: превью роли перестаёт называть глагол, которого не бывает |
| **перспективность** | **обратимо**: снятие помечает строку каталога, а не удаляет её (`RetireVerb`), и оживление — объявление того же глагола в манифесте. Внешне-адресуемая координата не трогается (ban #15), миграции данных арендатора нет |
| **безопасность** | поверхность **сужается**: перестают материализоваться кортежи, которых не читает никто. Ни один путь решения о доступе не меняется |
| **производственность** | режима «только для стенда» нет; отложенного нет; снятие идёт тем же путём, которым каталог принимает всякое изменение манифеста |

## 4. ЦЕНА СНЯТИЯ — премиса задачи ОПРОВЕРГНУТА замером

Тело `#1922` называет снятие «правкой канонической модели, раздела `resources`
манифеста и посева `catalog_verb`, **плюс новая миграция по живым строкам**», а
комментарий линии добавляет: «применённую править нельзя, ban #5».

**Половина про миграцию сегодня неверна.** Каталог модуля живёт данными
(эпик `#1027`), и у снятия глагола есть производитель:

```sh
git grep -n 'RetireVerb' -- internal/apps/kaname/modulecatalog/*.go | grep -v _test
# → apply.go:184  RetireVerb(ctx, v catalog.VerbRow, reason string) (bool, error)
# → apply.go:549  retired, terr := w.RetireVerb(ctx, v, reason)
```

План собирает корзину снятого из разности «что в базе» против «что объявлено
манифестом» (`internal/apps/kaname/modulecatalog/plan.go:180-192`, ветвь
`gone.Verbs`). То есть глагол, исчезнувший из манифеста, отзывается **как
данные**, применителем, а не миграцией; строка **помечается** снятой, поэтому
`role_rule_ref_verb_fk` держится, и `ON DELETE RESTRICT` не срабатывает.

Ban #5 при этом не задет: применённая миграция не правится.

**Что осталось верным из цены:** правка манифеста тянет за собой канон модели —
`internal/modelrender` рендерит из манифестов и сверяет с
`proto/kaname/cloud/iam/v1/fga_model.fga`, поэтому блок `type iam_role` обязан
измениться ТЕМ ЖЕ изменением, иначе сверка краснеет. Это гейт, а не риск.

## 5. Приёмочные сценарии (Given-When-Then)

### GWT-1 — отношение не объявлено ни манифестом, ни моделью

**Дано** дерево после изменения.
**Когда** читают объявление ресурса `role` в `manifest.yaml` и блок
`type iam_role` канонической модели.
**Тогда** ни одно из двух не называет `get`/`v_get`.
**И** порождённая таблица набора глаголов типа (`internal/authzmap/tables_gen.go`)
называет для `iam_role` ровно `{v_delete, v_list, v_update}`.

Предикат:
```sh
git grep -n "v_get" -- '*.go' ':!*_test.go' ':!pkg/api/*' | grep -i iam_role   # пусто
```

### GWT-2 — порождённое сошлось с входом (положительный контроль)

**Дано** то же дерево.
**Когда** прогоняют сверку свежести порождённых таблиц и сверку модели с
манифестами.
**Тогда** обе зелёные.

Близнец несущий: без него «`v_get` пропал» неотличимо от «порождение сломалось
и не производит ничего».

### GWT-3 — соседние глаголы типа не задеты

**Дано** то же дерево.
**Когда** держатель `iam.role.edit` обновляет роль, а держатель `iam.role.view`
читает перечень.
**Тогда** оба действия проходят как прежде.

Отрицание GWT-1 без этого зеленело бы на типе, у которого отняли всё.

### GWT-4 — превью роли перестало обещать глагол, которого нет

**Дано** роль `iam.role.admin` (правило `classes: ["*"]`).
**Когда** арендатор читает её превью.
**Тогда** среди эффективных глаголов **нет** `get`.
**И** остальные три глагола названы — превью не опустело.

Это и есть наблюдаемая арендатором половина изменения, и она названа здесь
именно потому, что видна ему.

### GWT-5 — паритет чтения роли не изменился

**Дано** держатель гранта по селектору роли (`v_list` без яруса).
**Когда** он читает роль поимённо и перечнем.
**Тогда** оба чтения отвечают одинаково: роль видна и там, и там.

Свойство держит существующая проба
`TestVisibleSet_RoleKeepsTheUnionItsOwnGetEnforces`; сценарий утверждает, что
изменение её не трогает — иначе выбранный исход превратился бы в отвергнутый.

### GWT-6 — строка каталога СНЯТА, а не удалена

**Дано** база, где строка `('iam','role','get')` жива.
**Когда** применитель каталога применяет манифест без этого глагола.
**Тогда** строка помечена снятой (`live = false`, названа причина), и число
строк таблицы не уменьшилось.
**И** ни одна применённая миграция не правлена.

### GWT-7 — снятие ОБРАТИМО

**Дано** база, где глагол снят.
**Когда** манифест снова объявляет `get` у ресурса `role`.
**Тогда** применитель оживляет ту же строку, а не заводит вторую.

Без этого сценария «обратимо» из §3.2 — обещание, а не свойство.

### GWT-8 — кортежи снятого глагола перестают материализоваться

**Дано** держатель подстановочной роли `iam.role.admin`.
**Когда** проекция глаголов роли пересчитывается.
**Тогда** кортежей `v_get` на объектах типа `iam_role` не появляется.
**И** решения о доступе ни по одному глаголу не изменились: ни один путь запроса
`v_get` на этом типе не спрашивал и до изменения.

### GWT-9 — послабление не переживает свой предмет

**Дано** любое место дерева, объяснявшее мёртвое отношение.
**Когда** отношение снято.
**Тогда** объяснение снято ТЕМ ЖЕ изменением.

Класс назван `testing.md` §«Гейт на класс» п. 9: негативное утверждение о снятом
предмете **замолкает**, а не краснеет, и заметить это нечем, кроме вопроса
«а бывает ли ещё вход, на котором оно падает».

## 6. Вне области

- **пп. 2–3 задачи `#1922`** — закрыты `#2047`, предикат пуст, перемерен дважды;
- **право `iam.roles.get` каталога прав** — запись стоит на фильтруемой полосе и
  этим изменением не трогается: она про ГЛАГОЛ КРАЯ, а не про отношение типа;
- **форма превью роли** (глаголы одним множеством, без разбивки по ресурсам) —
  своя задача; здесь превью только перестаёт называть снятый глагол;
- **прочие типы** `iam`: у шести из семи предикат страницы `{v_get}`, и он живой;
- **`v_get` на типах других модулей** — 27 записей каталога, все с читателем.

## 7. Готовность (DoD)

1. `manifest.yaml`: у ресурса `role` объявлены `[list, update, delete]`;
2. `proto/kaname/cloud/iam/v1/fga_model.fga`: блок `type iam_role` не объявляет
   `v_get`; вшитая копия модели сведена с канонической;
3. `internal/authzmap/tables_gen.go` перегенерирован, сверка свежести зелена;
4. сверка модели с манифестами (`internal/modelrender`) зелена;
5. интеграционная проба: применитель каталога **помечает** строку снятой и
   оживляет её обратно (GWT-6, GWT-7), число строк не меняется;
6. проба превью: `iam.role.admin` не называет `get` и называет остальные три
   (GWT-4, с положительным контролем);
7. `TestVisibleSet_RoleKeepsTheUnionItsOwnGetEnforces` зелена без правки (GWT-5);
8. перепись по дереву: вхождений `v_get` рядом с `iam_role` вне порождённого —
   ноль (GWT-1);
9. ни одна применённая миграция не правлена (ban #5).

## 7б. Открытое — числом

- **эффект на уже материализованные кортежи** `v_get@iam_role:*` у сегодняшних
  держателей `iam.role.admin`: их число на стенде с данными арендатора **не

## 8. Ревью

Вердикт ставит `acceptance-reviewer` — единственный gate APPROVED, и не заказчик.
Автор своего вердикта не ставит: строка «Статус» выше объявляет DRAFT, и
реализация по §5 закрыта до круга (ban #1).

**На что смотреть в первую очередь:**

1. §3.1 — довод против «дать читателя» опирается на существующую пробу; проверить
   её тело, а не пересказ;
2. §4 — опровержение премисы цены. Проверить `RetireVerb` и ветвь `gone.Verbs`
   вызовом предикатов, а не прочтением: если применитель глаголы НЕ отзывает,
   решение §3 остаётся верным, а DoD п. 5 обязан смениться на миграцию;
3. §5 GWT-4 — единственный сценарий, наблюдаемый арендатором. Если у превью
   найдётся второй производитель, сценарий неполон;
4. §2 — числа: у каждого предикат приведён; расхождение разрешать уточнением
   единицы счёта, а не выбором правдоподобного.
