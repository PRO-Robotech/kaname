# Приёмка: выход, произведённый распорядителем, назван в записи сессии своей причиной

- **Статус:** DRAFT — редакция 1, кругов ревью ноль; санкции на код нет (ban #1). Вердикт
  выносит `acceptance-reviewer`
- **Статическая форма:** DRAFT. Слово выше вписано и не означает вердикта. Действующее
  одобрение выводится из записи ревью по отпечатку этой редакции и из внешнего события, на
  которое запись ссылается (`change-graph.md` §2 «Вердикт привязан к ОТПЕЧАТКУ, а не к
  документу»). Шапка после ревью не правится
- **История ревью:** записей нет. Сюда только дописываются строки вида «дата · круг · вердикт
  · SHA-256 редакции · путь записи»; прежние строки не правятся и не удаляются
- **Дата:** 2026-09-23
- **Задача:** `PRO-Robotech/kaname#334`. Волна `#358`, эпик `#357`, цель линии —
  `PRO-Robotech/kacho#2564`. Тело задачи — источник признака и предиката снятия; здесь из
  него взят предмет, а довод о следствии не пересказывается (§1.2)
- **Ревизия измерения:** `cbbac984` — база линии, то есть ствол службы, от которого ветвится
  ветка эпика и её волны. Числа §0 сняты на дереве «эта база ПЛЮС дифф ветки волны `358` на
  момент написания». Где число на базе другое, названы оба значения. Коммит ветки волны здесь
  не называется. Гейт датировки судит вхождение ревизии в историю СТВОЛА, а вершина волны
  станет её предком только после вливания эпика. До вливания такая датировка была бы красной
  находкой «чужая линия». Приём взят у `refusal-text-names-the-lane-that-can-retry.md`
- **Тип изменения:** меняет значение, которое служба пишет в свою запись. Проводной контракт
  не меняется ни одним полем: ответ глагола, код, текст и форма операции остаются прежними
  (KN-SER-01, KN-SER-04)
- **Сервис:** `kaname`. Затрагиваются `internal/migrations/`, `internal/domain/` и
  `internal/apps/kaname/api/internal_iam/`
- **Предшественник:** полоса `#313` (запрос `#326`, влит в ветку волны). Она завела снятие
  НАШИХ записей сессии входа на пути принудительного выхода и записала туда `logout`, потому
  что четвёртого значения словарь не знал. Этот остаток полоса назвала в коде, у места
  записи, вместе с предикатом снятия

## §0. Перепись производителей — до сценариев

Каждое «Тогда» ниже опирается на производителя из этой переписи. Производитель, которого в
дереве ещё нет, помечен «заводит это изменение». Условие, которого схема не допускает, в
«Дано» не ставится.

### 0.1. Кто ПИШЕТ причину снятия записи сессии

Операторов записи **два**, в одном файле:

```sh
git grep -n 'ended_reason = \$' -- 'internal/**/*.go' ':!*_test.go'
# → internal/repo/kaname/pg/human_session_repo.go:278   (снятие одной записи)
# → internal/repo/kaname/pg/human_session_repo.go:306   (снятие записей личности, endSessionsOfSQL)
```

Оба оператора несут условие `ended_at IS NULL` (строки 279 и 307). Значит, запись снимается
один раз, и причину пишет тот, кто снял её первым. На этом стоит KN-SER-05.

Мест вызова, передающих причину, **пять** на вершине волны и **четыре** на базе:

```sh
git grep -n -E '\.(EndSession|EndOtherSessions|EndAllSessions)\(' -- '*.go' ':!*_test.go'
```

| место вызова | глагол | причина | на базе `cbbac984` |
|---|---|---|---|
| `humansession/logout.go:78` | собственный выход человека | `logout` | есть |
| `humansession/change_password.go:196` | смена пароля (гасит прочие) | `password-change` | есть |
| `humansession/recovery_complete.go:231` | завершение восстановления | `password-change` | есть |
| `humansession/sf_remove.go:123` | снятие второго фактора самим человеком | `second-factor-removed` | есть |
| `internal_iam/force_logout.go:422` | **принудительный выход распорядителем** | **`logout`** | **нет** |

Административный путь пишет в эту колонку **только на ветке волны**. На стволе принудительный
выход наших записей сессии не снимает вовсе:

```sh
git grep -c 'EndAllSessions' cbbac984 -- internal/apps/kaname/api/internal_iam/force_logout.go   # → пусто (0)
git grep -c 'EndAllSessions' -- internal/apps/kaname/api/internal_iam/force_logout.go             # → 2 (вызов и порт)
```

### 0.2. Кто ДЕРЖИТ словарь

Словарь держат два места, и сверки между ними сегодня нет.

**База.** Ограничение `human_sessions_ended_reason_check`. Определение стоит в трёх местах:
создание таблицы, накат второй миграции и её откат. Действует на голове второе:

```sh
git grep -n 'ADD CONSTRAINT human_sessions_ended_reason_check\|CONSTRAINT human_sessions_ended_reason_check CHECK' -- 'internal/migrations/*.sql'
# → 20260916190000_human_session_is_our_record.sql:89            logout · password-change
# → 20260917160000_second_factor_rows_carry_state_and_step.sql:100  + second-factor-removed   (накат)
# → 20260917160000_second_factor_rows_carry_state_and_step.sql:132  logout · password-change   (откат)
```

**Домен.** Константы `internal/domain/human_session.go:224-236`. Их **четыре**, и в словарь
снятия сессии входят только **три**. Четвёртая, `second-factor-reset`, — причина ОТСЕЧКИ.
Её пишет сброс второго фактора распорядителем, и ни одному снимающему методу она не
передаётся:

```sh
git grep -n 'RevokeReasonSecondFactorReset' -- '*.go' ':!*_test.go'
# → 3 строки: объявление (internal/domain/human_session.go:235),
#   internal/apps/kaname/api/user/reset_second_factor.go:185 (отсечка) и :197 (состав события); вызова End* нет
```

Эти константы служат сразу двум словарям: закрытому словарю снятия сессии и открытому полю
причины отсечки (`user_token_revocations_reason_check` — только длина ≤ 256). Поэтому
перечня «вот словарь снятия сессии» в домене сегодня нет. Его заводит KN-SER-07.

### 0.3. Кто ЧИТАЕТ причину

В продукте её не читает никто:

```sh
git grep -n 'ended_reason' -- '*.go' ':!*_test.go'
# → 5 строк: 3 комментария (force_logout.go:378, :414; human_session.go:230) и 2 оператора SET (§0.1).
#   Ни одного SELECT.
git grep -c -i -E 'ended_reason|endedReason' -- proto/   # → пусто (0): на проводе поля нет
```

Резолв сессии читает `ended_at`, а не причину (`resolveSQL`,
`internal/repo/kaname/pg/human_session_repo.go:49-57`; ветвь «снята» — строка 88-90). Уборка
тоже судит по `ended_at` (там же, строка 185). Отсюда два следствия. Новое значение не может
изменить ни ответ предъявителю, ни судьбу строки, и это держит KN-SER-04. А читатель у
колонки один — журнал службы, который читают при разборе.

### 0.4. Что отвергает база на этом входе

Значение вне словаря отвергается с именем ограничения
`human_sessions_ended_reason_check`. Проба-сосед —
`TestHumanSessionSchema_LevelAndMethodsAreHeldByTheBase`
(`internal/migrations/human_session_schema_integration_test.go:86-87`, значение `sneeze`).
Сегодня так отвергается и `admin-force-logout`: в миграциях значения нет.

```sh
git grep -c 'admin-force-logout' -- 'internal/migrations/*.sql'   # → пусто (0)
```

### 0.5. Где уже стоит это слово

Слово `admin-force-logout` в не-тестовом Go присвоено **одно**. Это умолчание СВОБОДНОЙ
причины отсечки, когда запрос причины не несёт:

```sh
git grep -n '"admin-force-logout"' -- 'internal/**/*.go' ':!*_test.go'
# → internal/apps/kaname/api/internal_iam/force_logout.go:276   reason = "admin-force-logout"
```

То же слово контракт называет умолчанием поля `reason` в `ForceLogoutRequest`
(`proto/kaname/cloud/iam/v1/internal_iam_service.proto:493-496`). Поле описано как «свободная
причина на записи отсечки и в событии». О записи сессии контракт не говорит ничего, и это
изменение этого не меняет (§2).

## §1. Предмет

### 1.1. Что меняется

На посадке `own` принудительный выход снимает наши записи сессии входа. Сегодня (на ветке
волны) он пишет в них причину `logout`, то есть ту же, что собственный выход человека. После
этого изменения он пишет **`admin-force-logout`** — четвёртое значение закрытого словаря
снятия сессии. Словарь при этом объявляется в домене одним перечнем, и база сверяется с ним в
обе стороны.

Ответ глагола не меняется, ответ предъявителю тоже. Меняется только то, что служба записывает
о снятой сессии в свой журнал. Норма та же, что уже стоит в Ф1 для отсечки: журнал обязан
отличать выход от смены пароля (Ф1-63), а причина отзыва — это наш журнал, а не ответ
предъявителю (Ф1-17, `login-session-and-credentials-are-our-contract.md` §3.3). Действующий
текст Ф1 одобрен: запись ревью круга 11 стоит на его отпечатке
(`docs/specs/reviews/login-session-and-credentials-are-our-contract/7bdef287….yaml`,
`APPROVED`, сверено `sha256sum` на вершине волны). Здесь то же правило применено к записи
сессии.

### 1.2. Почему — ссылкой, а не пересказом

Довод о следствии изложен в задаче и здесь не повторяется. Репозиторий публичен
(`security-disclosure.md` §«Публичные артефакты»), и приёмка — не место для этого разбора.
Предмет выражен сценариями: запись сессии называет того, кто её снял.

### 1.3. Почему сейчас, и чем это измерено

Значение **добавляется**. Обратного заполнения нет (KN-SER-08), и нет потому, что оно
не нужно. На стволе административный путь в эту колонку не пишет вовсе (§0.1, 0 на
`cbbac984`), значит ни одна строка, записанная стволом, не помечена неверно. Путь, пишущий
`logout`, живёт только в ветке эпика и вливается в `main` тем же запросом эпика, что и это
изменение (порядок вливания — тело `#357`, «Ветки»). Условие названо, потому что посылка на
нём держится: приди `#313` в ствол без этого изменения, строки ствола получили бы `logout` от
распорядителя. Решения о прошлом, верного для таких строк, нет.

## §2. Что НЕ входит

- **Состав и порядок события принудительного выхода.** Событие кладётся транзакцией отсечки
  до снятия и числа снятых записей не несёт. Это предмет `#340`, у него свой вопрос о
  частичном исходе.
- **Словарь причин отзыва семейства** (`token_families_revoked_reason_ck`) — предмет `#339`.
  Снятие сессии отзывает выданное в ней причиной семейства `session-ended`. Это изменение её
  не трогает.
- **Причина отсечки.** Поле остаётся свободным: причина из запроса распорядителя или умолчание
  (KN-SER-02). Ограничение `user_token_revocations_reason_check` не меняется.
- **Проводной контракт.** Ни `proto`, ни REST, ни ответ `ForceLogout`, ни текст отказа не
  меняются. Причину снятия сессии наружу не выводит ни одно чтение (§0.3), и вывод её в
  контракт этим изменением не заводится.
- **Посадка `external`.** Там полоса входа не поднимается, наших записей сессии нет, и снимает
  сессию внешний поставщик (`ProviderSessions`). Писать в колонку там нечему.
- **Прочие четыре писателя** (§0.1) — их значения не меняются. KN-SER-03 держит одного из них
  как близнеца.
- **Строки стендов**, которым ветка эпика уже записала `logout` от распорядителя. Они неотличимы
  от выхода человека по построению, и отличить их нечем. Изменение их не переписывает
  (KN-SER-08) и о них ничего не утверждает. Уборка снесёт их по сроку наравне с прочими
  снятыми (§0.3).

## §3. Решения

### Р1. Значение — `admin-force-logout`

Слово берётся из предиката снятия задачи дословно. Форма — строчные буквы через дефис, как у
трёх соседей словаря. Это же слово служба уже пишет умолчанием причины отсечки (§0.5), и
совпадение намеренное: предмет у обеих записей один — принудительный выход.

### Р2. Значение закрытого словаря не берётся из запроса

Причина в `ForceLogoutRequest.reason` — свободный текст распорядителя. Она по-прежнему идёт в
отсечку и в событие. В запись сессии она не идёт: запись сессии получает значение закрытого
словаря, и только его. Иначе всякая причина, отличная от слова словаря, стоила бы самого
выхода — база отвергла бы снятие, и глагол ответил бы отказом. Держит это KN-SER-02.

### Р3. Слово объявлено один раз

Домен объявляет значение один раз и объявляет перечень словаря снятия сессии. Умолчание
причины отсечки и причина снятия сессии ссылаются на это объявление, а не повторяют литерал.
Держит это KN-SER-10. Второе место — комментарий контракта (§0.5). Он описывает умолчание для
интегратора и остаётся как есть: слово не меняется, и контракт этим изменением не правится.
Держателя у пары «объявление домена — комментарий контракта» нет, и это сказано прямо. Смена
слова была бы изменением контракта со своей приёмкой, и правила бы оба места.

### Р4. Накат лежащих строк не трогает

Миграция только расширяет ограничение, операторов данных в накате нет (KN-SER-08). Довод —
§1.3.

### Р5. Откат переводит `admin-force-logout` в `logout`

Откат возвращает словарь из трёх значений и переводит строки с новым значением в `logout`.
Факт снятия и его момент (`ended_at`) откат не трогает. Форма та же, что у отката миграции
`20260917160000`: там `second-factor-removed` переводится в `password-change`, потому что
«сессии сняты, и остаются снятыми». Выбор значения не произвольный: `logout` — ровно то, что
код до этого изменения писал для того же акта. После отката база и код снова согласны.
Различение при этом теряется. Это свойство отката в словарь, где различения нет, и
восстановить его не взялся бы ни один способ. Отказ от отката был бы хуже: пока есть
снятые распорядителем строки, откат стал бы невыполнимым, а живут такие строки до уборки.
Держит это KN-SER-09.

## §4. Сценарии

Посадка во всех сценариях, кроме схемных (06–09) и сценария дерева (10), — `own`. Вызывающий
`InternalIAMService.ForceLogout` — субъект, у которого есть `system_admin` на `cluster`.
Страж и отказы стража не меняются, и сценарии их не утверждают. У каждого сценария назван
производитель «Тогда». У отрицательного и различающего сценария названа дельта против
близнеца, и она равна ровно одному факту.

### KN-SER-01 · принудительный выход без причины в запросе — запись сессии несёт `admin-force-logout`

> **Дано** личность P в состоянии `ACTIVE` и одна её живая запись сессии S. Запись положена
> тем же писателем, которым её кладёт полоса входа
> **Когда** вызывается `kaname.cloud.iam.v1.InternalIAMService/ForceLogout` с телом:
>   - `user_id` = идентификатор P
>   - `reason` не задан
>
> **Тогда** операция завершена: `done = true`, `error` пуст, `metadata` =
> `ForceLogoutMetadata{ userId: P }`, `response` = `ForceLogoutResult{ revokedCount: 1 }`, и
> `OperationService.Get(id)` отдаёт то же самое
> **И** у S стоят `ended_at` и `ended_reason = 'admin-force-logout'`
> **И** в журнале отсечек у P причина `admin-force-logout`, актор — вызывающий

Первый факт — положительный контроль: форма ответа не изменилась. Второй — сам предмет.
Третий фиксирует, что причина отсечки прежняя.

**Производители:** значение пишет вызов снятия в `internal_iam/force_logout.go`, аргументом
служит объявление домена (заводит это изменение). Принимает значение ограничение, которое
расширяет новая миграция (заводит это изменение). Оператор — `endSessionsOfSQL`
(`human_session_repo.go:305`). Ответ операции даёт `forceLogoutOperationPayload`
(`force_logout.go`), и держит его прежняя проба
`TestForceLogout_OperationIsPersistedAndCompletes`.

**Красный до правки:** проба `TestForceLogout_EndsOurOwnLoginSession` утверждает сегодня
`domain.RevokeReasonLogout`. Её утверждение меняется на новое значение и краснеет, пока
глагол пишет `logout`. Интеграционная половина читает `ended_reason` строки S из базы. На
дереве «код правлен, миграции нет» она краснеет отказом глагола: база отвергает значение, и
операция не завершается успехом.

### KN-SER-02 · свободная причина из запроса не доходит до закрытой колонки

> **Дано** то же, что в KN-SER-01
> **Когда** `ForceLogout` вызывается с телом:
>   - `user_id` = идентификатор P
>   - `reason` = `incident-4711`
>
> **Тогда** операция завершена: `done = true`, `error` пуст
> **И** у S `ended_reason = 'admin-force-logout'`
> **И** в журнале отсечек у P причина `incident-4711`

**Дельта против KN-SER-01 — один факт:** в запросе есть свободная причина. Сценарий отделяет
верную реализацию от той, что передаёт в снятие причину из запроса. На KN-SER-01 обе
зелены, потому что умолчание совпадает со словом словаря (Р1). Здесь вторая краснеет: база
отвергает `incident-4711`, снятие отказывает, и глагол отвечает `UNAVAILABLE`
`could not end the login session`.

**Производители:** значение сессии — то же, что в KN-SER-01. Причину отсечки пишет
`SessionRevocationsAdapter.RevokeAllUserTokensTx`
(`internal/repo/kaname/pg/hook_pool_adapters.go:170`), без изменений.

### KN-SER-03 · собственный выход человека по-прежнему пишет `logout` (близнец KN-SER-01)

> **Дано** личность Q в состоянии `ACTIVE` и одна её живая запись сессии T, на той же базе
> **Когда** Q выполняет собственный выход носителем T (глагол выхода полосы входа)

**Дельта против KN-SER-01 — один факт:** кто выполнил выход. Без этого близнеца KN-SER-01

**Производитель:** `humansession/logout.go:78` (`EndSession` с `domain.RevokeReasonLogout`),

### KN-SER-05 · причину пишет тот, кто снял запись первым

> **Дано** живая запись S личности P
> **Когда** P выполняет собственный выход носителем S, а затем распорядитель выполняет
> `ForceLogout` для P
> **Тогда** `ForceLogout` завершён успехом (снимать было нечего, и это законный исход)
> **И** у S `ended_reason = 'logout'`, а `ended_at` — момент собственного выхода, а не
> принудительного

> **Дано** живая запись S′ личности P′
> **Когда** распорядитель выполняет `ForceLogout` для P′, а затем P′ выполняет собственный
> выход носителем S′
> **Тогда** выход отвечает тем же исходом, что на отсутствующую сессию (Ф3-18), и ничего не пишет
> **И** у S′ `ended_reason = 'admin-force-logout'`, а `ended_at` — момент принудительного
> выхода

> **Дано** живая запись S″ личности P″
> **Когда** собственный выход носителем S″ и `ForceLogout` для P″ идут одновременно; раунд
> повторяется на свежей записи не меньше двадцати раз
> **Тогда** в каждом раунде оба глагола отвечают успехом
> **И** запись снята ровно один раз, и её причина — ровно одно из двух значений: `logout`
> либо `admin-force-logout`
> **И** проба печатает, сколько раундов выиграл каждый акт

**Дельта между первыми двумя половинами — один факт:** порядок двух актов. Журнал обязан
называть акт, который снял запись на самом деле. Второй акт причину не переписывает, иначе
запись называла бы того, кто пришёл позже. Третья половина — спорный путь без порядка. Какой
акт выиграет, она не утверждает: это решает база. Она утверждает, что проигравший не
отказывает и не пишет своего. Число выигрышей печатается, а не требуется: исход гонки не
детерминирован, и требование «оба выиграли хоть раз» краснело бы по жребию.

**Производители:** условие `ended_at IS NULL` в обоих операторах
(`human_session_repo.go:279`, `:307`) и ранний выход собственного выхода на «сессии нет»
(`humansession/logout.go:65-70`). Все три без изменений. Одновременная пара «снятие одной
записи против снятия записей личности» пробы сегодня не имеет:
`human_session_repo_integration_test.go` гоняет параллельно только первую аутентификацию и
замещение материала. Эту пробу заводит это изменение. Сценарий утверждает, что новое значение
этим свойством не обходится.

### KN-SER-06 · база принимает новое значение и по-прежнему отвергает чужое

> **Дано** база на голове миграций; пять живых записей
> **Когда** первая снимается с причиной `admin-force-logout`
> **Тогда** база принимает
> **Когда** вторая снимается с причиной `sneeze`
> **Тогда** база отвергает, ограничение — `human_sessions_ended_reason_check`
> **Когда** третья, четвёртая и пятая снимаются с `logout`, `password-change` и
> `second-factor-removed` соответственно
> **Тогда** база принимает все три

**Дельта между принятием и отказом — один факт:** значение причины. Записи разные, но
одинаковые по состоянию (живые, одной личности), и оператор с моментом у них один.

**Производитель:** новая миграция (заводит это изменение). Форма — соседа,

**Красный до правки:** на голове без новой миграции первое снятие отвергается тем же

### KN-SER-07 · словарь объявлен в домене одним перечнем, и база совпадает с ним в обе стороны

> **Дано** база на голове миграций и перечень словаря снятия сессии, объявленный доменом

> **И** в перечне нет `second-factor-reset`: это причина отсечки, а не снятия сессии (§0.2)

Форма — `TestHumanSessionMethodVocabularyAgreesWithTheRule` у соседней колонки той же
таблицы: словарь в ограничении сверяется с производителем, а не выписывается вторым местом.

**Способность упасть — в обе стороны, и обе исполнены.** Направление «домен шире базы» даёт

ограничения с лишним значением в кавычках. Проба обязана краснеть и назвать это значение.

### KN-SER-08 · накат не переписывает лежащие строки

> **Дано** база, накатанная до версии, предшествующей новой миграции. На ней снятые записи

**Производитель:** раздел наката новой миграции (заводит это изменение). Операторов данных в

### KN-SER-09 · откат возвращает словарь из трёх; снятые распорядителем становятся `logout`; повторный накат сходится

## §6. Признак готовности (DoD)

Каждый пункт имеет объективное «пройдено / не пройдено».
