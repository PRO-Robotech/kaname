## Предлагаемая поправка §0.1/R1 #982

`project`, `parent`, `owner` сохраняют прежнее правило. Дополнительное имя
отношения допустимо **только как точный именованный указатель `parents` живого
каталога**, с точным типом субъекта той же декларации. `writes` не расширяет
набор имён отношений: для него сохраняется прежний closed-three и точная пара
отношение/тип субъекта. Literal `box` в PM03/PM04 сохраняется, не переименовывается
в `parent` и не становится глобальным исключением corelib.

Допуск завершает use-case в той же TX до записи факта: аутентифицированный
выпускающий модуль владеет типом, каталог жив, тройка совпадает, родитель —
существующий проект либо зарегистрированный контейнер, прежние DP/PB судят
claims без заполнения пропусков, authority подтверждена для **всех** выведенных
canonical accounts. IAM/root/direct-account отрицания сохраняются. Публикация
для анонима остаётся отдельным закрытым путём. Handler не является единственной
границей: прямой вызов use-case проходит тот же допуск.

## Обратный жизненный цикл

После законного допуска именованного указателя в той же TX сохраняется exact
claim: canonical module, model object type/id, literal relation, полный subject,
монотонная версия и признак действующего владения. Claim, зеркало, журнал,
аудит и событие сверки фиксируются либо откатываются вместе. Отсутствие версии
сохраняет прежнюю семантику legacy-производителя, без выдуманной версии часов.

Текущий versionless mode хранится отдельно от монотонного ordered watermark.
Versionless Register принимается и после конечной active/inactive истории,
не понижая watermark; последующий ordered replay остаётся под собственным
fence. Каскадное снятие сохраняет и использует собственную версию/режим
удалённого ребёнка, не временную шкалу parent tombstone.

Unregister и снятие потомков используют сохранённую принадлежность, включая
policy shrink и retirement. Текущий каталог не является источником прежнего
владения. Никакого backfill из scopes, standing facts, outbox или текущих parents
нет; неизвестный named tuple не присваивается и не объявляется снятым.
Неизвестная пара запроса на снятие не получает разрешение из похожей live policy.
История claim переживает снятие, чтобы повтор был проверяемым; более старое
надгробие не снимает новую claim, равная/старая версия не воскрешает снятую
версионную регистрацию. Новая версия может зарегистрировать тот же ключ снова.

Независимый ACTIVE AB holder сохраняет факт при снятии registrar; действующая
named claim сохраняет факт при отзыве AB. В обоих порядках свёртка сначала
запирает точный факт, затем отдельным оператором перечитывает держателей на
свежем READ COMMITTED. Holder read не берёт обратных замков binding/mirror/claim.
Все claim changes lifecycle предшествуют первому fact lock. Последний holder
обязан снять факт даже при разных шкалах AB/owner: исключение к сравнению
агрегированной версии ограничено exact saved named identity, доказанным
отсутствием держателей и допустимой версией снятия claim; legacy сравнения не
меняются. Публикация не смешивается с этой веткой.

Downgrade сначала берёт несовместимый table lock, затем отдельным свежим
оператором проверяет history. С сохраняющимися claims он отказывает: уничтожать единственное
provenance, оставляя named facts, нельзя. Reconciliation/quiescence перед
удалением истории является явным действием, не автоматическим удалением фактов.

## Проверяемые пары и ограничения доказательства

Сохраняются исходные PM03/PM04, AW/DP/PB, все 18 Strength точек и их сроки.
Дополнительные пары: точный pointer/неизвестное имя/wrong type/wrong module/
неизвестный контейнер/отсутствующая account authority; policy shrink и retirement
с прямым и descendant cleanup; отсутствие provenance; old/equal/new версии и
повтор; оба порядка независимых holders, mixed timestamps, caller rollback и
детерминированные гонки grant/revoke. Runtime результаты на новом diff ещё не
получены. Новый отпечаток этой поправки должен пройти действующий процесс
приёмочного review; исторические `APPROVED` соседних текстов на неё не переносятся.

Потребитель SvcRegistry и продукт Kacho в объём не входят.
