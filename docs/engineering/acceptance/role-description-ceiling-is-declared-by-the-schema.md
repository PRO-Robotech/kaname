## Обзор

Назначение роли (`roles[].description` манифеста модуля) ограничено сверху 256 знаками в трёх
местах: доменный тип (`domain.DescriptionMax`, счёт `utf8.RuneCountInString`), ограничение
базы `roles_description_check` (`length(description) <= 256`, Postgres считает знаки) и — после
`#867` — загрузчик манифеста, который судит тем же доменным типом. Опубликованная схема
`schema/module-manifest.schema.json` — контракт для автора манифеста и его редактора — несёт у
этого поля только `minLength: 1`. Редактор автора молчит там, где загрузчик откажет.

Изменение объявляет предел в схеме, называет в ней единицу счёта и заводит пробу, которая
сверяет предел схемы с загрузчиком по обе стороны границы.

## Вне объёма

1. Загрузчик и доменный тип — не меняются (`#867` закрыта).
2. Предел описания у `sa_keys` и `user_tokens` — `#864`.
3. Прочие строковые поля схемы без верхнего предела — не предмет; проба Р3 судит всякий
   `maxLength`, который схема объявит, но новых пределов, кроме этого, изменение не вводит.
4. Край, консоль: поле не наружное — манифест доставляется службе, а не арендатору.

## Решения

**Р1. Предел и единица объявлены схемой.** У `roles.items.properties.description`:
`"maxLength": 256` рядом с `"minLength": 1`. Описание поля называет оба предела, единицу —
**знак, то есть кодовую точку Unicode** (так считают `maxLength` JSON Schema 2020-12, Go
`utf8.RuneCountInString` и Postgres `length()`), — и то, что считается значение после разбора
YAML: перевод строки, который добавляет блочная запись `>` или `|`, — тоже знак. Фраза
нынешнего описания «Пригодность назначения держит побайтовая сверка с живой строкой, а не
предел длины» приводится к правде: сверка держит нижнюю границу, верхнюю — предел домена.

**Р2. Согласие — пробой, а не текстом.** Схема не исполняется кодом службы, поэтому её
предел сверяется с загрузчиком тем же способом, что `minLength`: проба читает предел из
опубликованной схемы и отдаёт `Load` значение на границе и на знак выше.

**Р3. Проба знает `maxLength` в обе стороны.** Обход требовательности распознаёт `maxLength`:
по каждому объявлению — значение в пределе принимается `Load`, на знак выше — отвергается.
Отдельно утверждается, что предел схемы у `roles[].description` равен `domain.DescriptionMax`:
без этого схема, вовсе не объявившая предел, давала бы пробе «судить нечего» вместо красного.

## Как строится «Дано»

- **П1** — манифест из пробы `#867`: модуль `iam`, одна роль `iam.role.edit` с ярусом
  `{tierType: iam.cluster, tierId: cluster_root}` и правилом
  `{module: iam, resources: [role], classes: [get, list, update]}`; поле `description` — из
  сценария. Строится строкой в пробе, посев базы не нужен.
- **П2** — опубликованная схема `schema/module-manifest.schema.json`, прочитанная пробой как
  файл дерева.

## Сценарии

### RD-01 — схема объявляет предел домена

**Дано** П2.
**Когда** проба читает `properties.roles.items.properties.description`.
**Тогда** `maxLength` = 256 = `domain.DescriptionMax`; `minLength` = 1.
**И** описание поля содержит число `256` и слово «кодов» (кодовая точка) — единица названа.
**Сегодня** — красное: `maxLength` нет.
**Близнец (отрицание пробы):** копия схемы с `maxLength` 255 → проба красная с текстом,
называющим путь `roles[].description` и оба числа (255 и 256). Отличие — одно число.

### RD-02 — граница по обе стороны, граница взята из схемы

**Дано** П1, П2.
**Когда** `Load` получает `description` из 256 знаков `a` в двойных кавычках; затем из 257.
**Тогда** 256 — принято; 257 — отказ `ErrRoleDescriptionTooLong`, текст
`roles[0].description: 257 знаков, допускается не более 256 — применитель ролей отверг бы такое назначение на старте службы: Illegal argument description: length must be <=256`.
**Близнец:** 256 для 257 — одно число. Исход загрузчика сегодня уже такой (замер); новое —
что граница берётся из схемы (Р2), поэтому проба сегодня красная на чтении предела.

### RD-03 — единица счёта — знак, а не байт и не единица UTF-16

**Дано** П1.
**Когда** `description` — (а) 256 знаков `😀` (U+1F600: 1024 байта UTF-8, 512 единиц UTF-16);
(б) 257 таких знаков; (в) 200 знаков `ж` (400 байт).
**Тогда** (а) принято; (б) отказ с тем же текстом, что RD-02, «257 знаков»; (в) принято.
**Близнец:** (а) для (б) — один знак.

### RD-04 — перевод строки блочной записи считается

**Дано** П1.
**Когда** `description` записан блоком `>` (строка из 256 знаков `a` на следующей строке с
отступом); затем тем же блоком `>-`.
**Тогда** `>` — отказ, текст RD-02 с «257 знаков» (значение несёт завершающий перевод строки);
`>-` — принято.
**Близнец:** `>-` для `>` — один индикатор: перевод строки отсечён.
Сценарий фиксирует, что считается то значение, которое применитель пишет в строку дословно,
и что Р1 называет это в схеме.

### RD-05 — `maxLength`, объявленный схемой, судится, а не пропускается

**Дано** копия схемы П2, у которой `maxLength` у `roles[].description` поднят до 300.
**Когда** проба согласия обходит копию.
**Тогда** проба красная: `Load` отвергает 300 знаков, а схема их объявила допустимыми; текст
находки называет путь `roles[].description` и предел `300`.
**Близнец:** нетронутая схема (после Р1) — проба зелёная, перепись печатает число судимых
`maxLength` ≥ 1 (обход, осмотревший ноль, зелёным не считается).
**Сегодня** — `maxLength` у обхода в перечне аннотаций: объявленный предел не судился бы.
