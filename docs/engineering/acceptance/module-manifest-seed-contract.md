**Предмет — два места об одном предмете, заведённые этой же правкой.** До неё шапка
была верна: сценарий такую половину нёс. После неё сценарий её не несёт, а шапка
продолжает утверждать обратное — причём в present tense и без единой пометки, что
цитата историческая. Читатель, пришедший из кода в приёмку, не найдёт названного и
заключит одно из двух: либо шапка устарела, либо приёмку молча ослабили. Оба вывода
ложны, и оба стоят захода.

**Это ровно тот довод, который правка приводит про себя.** Врезка §5.1 объясняет,

цитата как раз и уцелела, представленная как «вторая половина сценария».

**Корпус называет этот класс поимённо и требует правки тем же изменением:**

второе место об одном предмете и переживает снятую ветвь молча», с наблюдавшимся
прецедентом. Отдельного круга этот класс не заслуживал бы, если бы правка не
**сослалась** на эту самую шапку как на свой авторитет.

**Что сделать — минимально.** Переписать шапку так, чтобы она называла третье «И»

**Предикат снятия Р1** — обе стороны, потому что односторонний зеленел бы на пустой

## 1. Предмет

Домен объявляет платформе, что он такое: какие у него ресурсы, какие роли, какие
глаголы сняты и что нужно посеять при подъёме. Сегодня этого объявления нет
вовсе — предикат: `git ls-files | grep -icE 'manifest'` → **0** файлов индекса.

Черновик формы существует и доказан, но живёт **вне git** — в рабочем каталоге
воркспейса, у которого нет ревизии. Пока он там, у него нет ни владельца, ни
момента, когда его сверят: два места об одном предмете, из которых верно то,
которое читатель откроет первым.

### 1.1. Что показал замер — посылка задачи неверна вчетверо

Тело `#1088` говорит «схема написана по разделам `resources`, `roles`,
`deprecatedVerbs`, `seed`; осталось положить в дерево». Измерено:

| Утверждение задачи | Предикат | Что измерено |
|---|---|---|
| «схема написана» | `python3 -c "import yaml;print(list(yaml.safe_load(open('seed.schema.yaml'))['properties']))"` — **свойств корня схемы**, шт. | `[serviceAccounts, groups, accessBindings, joins]` — покрыт **1 раздел**; `$id` = `.../module-manifest-seed.yaml`, `title` = «Раздел seed манифеста домена» |
| «разделов четыре» | `python3 -c "import yaml;print(list(yaml.safe_load(open('vpc.manifest.yaml'))))"` — **ключей верхнего уровня**, шт. | **6**: `apiVersion` (`iam/v1`), `module` (`vpc`), `resources`, `deprecatedVerbs`, `roles`, `seed`. Два первых задачей не названы вовсе |
| «238 строк» | `wc -l seed.schema.yaml` — **строк**, шт. | **272** |
| «4 законных близнеца» | разбор списка `CASES` в `tools/schema-inject.py` | утверждений **31**, ожидание `red` — 25, `green` — 6, из шести одно есть контроль неиспорченного |

Схем разделов `resources` (10 записей, 95 действий), `roles` (6) и
`deprecatedVerbs` (1) — **ноль строк**. То есть `#1088` не перенос, а работа, и
объём её втрое больше заявленного.

**Следствие для тела задачи:** его надо переписать по факту. Пока оно не
поправлено, оно тиражирует посылки, на которых нельзя строить план, — а его
следующий исполнитель прочитает первым.

### 1.2. Два ключа, которых задача не назвала, делают манифест невыразимым

Это не педантизм, а прямой вход в класс «два правила об одном поле»
(`api-conventions.md` §«Неисполнимая возможность»). Схема, написанная по телу
задачи, `apiVersion` и `module` не описывает. Загрузчик, отвергающий неизвестный
ключ, их отвергнет. Тогда **реальный манифест не проходит ни при каком значении**:
он объявлен, задокументирован, покрыт типами — и не загружается никогда.

Обе половины по отдельности защитимы; неверен их стык, и виден он только вызовом.

## 2. Решение

### 2.1. Форму судит ОДИН исполнитель, и это Go-структуры

**Решение: форму манифеста исполняет разбор в `services/iam/internal/manifest` —
Go-структуры плюс `Decoder.KnownFields(true)`. Схема `.json` остаётся ОПУБЛИКОВАННЫМ
контрактом для автора манифеста и внешней оснастки, а не вторым судьёй.**

Место загрузчика — отдельное решение со своей ценой, и оно принято в §2.7: здесь
названо, ЧЕМ судится форма, там — ГДЕ этот судья живёт.

Довод не в экономии, а в замере:

| Факт | Предикат | Значение |
|---|---|---|
| библиотеки JSON Schema для Go в дереве нет | `grep -icE 'santhosh\|xeipuuv\|qri-io\|invopop\|kaptinlin' go.sum` — **совпадений**, шт. | **0** |
| YAML читается одной прямой библиотекой | `grep -nE 'yaml' go.mod` | `gopkg.in/yaml.v3 v3.0.1` прямая; `go.yaml.in/yaml/v3 v3.0.5` помечена `// indirect` |
| прод-импортёров у неё | `git grep -l 'gopkg.in/yaml.v3' -- '*.go' \| grep -v _test.go` — **прод-файлов**, шт. | **3** |
| механизм отказа на неизвестном ключе уже есть и не использован | `git grep -c 'KnownFields' -- '*.go'` — **файлов**, шт. | **0** (код возврата 1) |

Завести библиотеку JSON Schema значит завести **два места об одном предмете** —
схему и Go-структуру, — за согласием которых в дереве не следит ничто. Разойдутся
они молча и ровно там, где расхождение не видно: **оба отвечают «валидно» на
валидном входе**, а расходятся только на невалидном.

`KnownFields(true)` замерен на способность называть предмет — не объявлен годным,
а проверен:

```
верхний уровень   → yaml: unmarshal errors: line 3: field resourcez not found in type manifest
глубина 3         → yaml: unmarshal errors: line 7: field clazz not found in type verb
законный близнец  → <nil>
```

Называет **и поле, и номер строки**, на любой глубине; на законном близнеце молчит.

### 2.2. Ключ-нестрока держится в ДЕКОДЕРЕ, а не в валидаторе связности

Задача относит это свойство к валидатору связности. **Это её пятая неверная
посылка**, и промах здесь не стилистический: к моменту связности предмета уже нет.

Замер на `gopkg.in/yaml.v3 v3.0.1`:

```
типизированная цель map[string]map[string]string
  вход:  grant: {on: a, true: b}
  err:   <nil>
  итог:  map[grant:map[on:a true:b]]     ← булев ключ стал строкой "true" МОЛЧА
```

Отличим он только на уровне разбора, до приведения к типу:

| ось | предикат | значение |
|---|---|---|
| ключей-нестрок **по тегу узла** (`yaml.Node.Tag != "!!str"`) | обход `yaml.Node` документа из 17 ключей | **6**: `true`(`!!bool`), `false`(`!!bool`), `null`(`!!null`), `~`(`!!null`), `123`(`!!int`), `0x1f`(`!!int`) — каждый с номером строки |
| ключей-нестрок **в разобранной карте** (`map[any]any`) | те же 17 ключей | **5** — `null` и `~` дают один и тот же ключ `nil` |
| **ключей в карте всего** | там же | **16** при 17 написанных |
| законный близнец: те же ключи **в кавычках** | обход `yaml.Node` | нестрок **0** |

Две последние строки — самостоятельная находка, которой нет ни в теле задачи, ни
в разведке: **`null:` и `~:` схлопываются в один ключ, одно значение теряется
молча**. Тот же класс, что известен по PyYAML, живой и на нашей библиотеке.

Единицы счёта здесь разные (**узлов** против **ключей карты**), и потому числа
разные; ни одно не «правильнее» — они меряют разное.

**Ловушка из тела задачи названа неверно для целевой библиотеки.** На
`gopkg.in/yaml.v3` строкой **остаются все десять** перечисленных там ключей
(`on off yes no y n On OFF Yes NO`): это свойство YAML 1.1, а ядро v3 — YAML 1.2.
Кто починит по тексту задачи, напишет проверку, которая **не найдёт ничего и будет
зелена всегда**, а настоящие шесть форм останутся невидимы.

### 2.3. Три свойства связности схемой НЕВЫРАЗИМЫ — измерено, а не принято на слово

`jsonschema.Draft202012Validator` по `seed.schema.yaml` на копии реального раздела
`seed` манифеста vpc:

| # | правка | исход схемы |
|---|---|---|
| — | **контроль: неиспорченный раздел** | **МОЛЧИТ** |
| 1 | `roleId` = `vpc.nosuchRole` — форма годна, роли в `roles` нет | **МОЛЧИТ** |
| 2 | субъект годной формы, посевом не заведён | **МОЛЧИТ** |
| 3 | группа с годным именем, ни одной выдачи на неё | **МОЛЧИТ** |
| 4 | булев ключ верхнего уровня | **КРАСНЕЕТ**, но текстом `Additional properties are not allowed (True was unexpected)` |

Контроль молчит — значит молчание в строках 1–3 не вакуумно.

Строка 4 — не «выразимо». Диагноз **ложный**: он говорит о лишнем свойстве, а
предмет — тип ключа. Читатель пойдёт искать опечатку в имени.

> **Первая попытка этого замера была негодной, и это записано, чтобы не повторили.**
> Я подставил `roleId = 'нет-такой-роли'`, субъект другой формы и группу с именем
> кириллицей — все три покраснели, и покраснели **на форме**: образец имени,
> перечень свойств. Инъекция, роняющая **не то**, доказательством не является
> (`testing.md` §«Гейт на класс», п. 2в). Годная форма — нарушить **только**
> проверяемое свойство, оставив всё остальное годным.

### 2.4. Что входит в эту под-фазу, и почему именно столько

**Входит:** оболочка манифеста (`apiVersion`, `module`) и раздел `seed` целиком —
опубликованная схема, загрузчик, валидатор связности, наборы инъекций, цель
сборки-проверка.

**«Целиком» — это ЧЕТЫРЕ подраздела, и четвёртый живёт по своему правилу.**
`serviceAccounts` · `groups` · `accessBindings` · **`joins`**. У `joins` связность
асимметрична и это не оговорка формы: вступают в **чужую** группу, объявленную другим
манифестом, поэтому требовать её присутствия в `seed.groups` **нельзя** — требование
покраснело бы на настоящем манифесте (§0.2, §5.7). Сценарии — §5.7; **порядок установки**,
выводимый из вступлений, в эту под-фазу не входит (§4), потому что он межманифестный, а
манифестов в дереве ноль.

**Каждая часть production-complete в своих границах** (ban #14): загрузчик
полностью проверяет всё, что ему дают, — форму, тип ключа и связность; отказ
называет поле и строку; ни одного места «пока happy-path», ни одного заглушечного
исхода.

**Раздел `seed` идёт первым не по удобству, а по замеру зависимости.**

| ключ | читатель в черновике | зависит ли от развилки `#1104` |
|---|---|---|
| `seed.*` (4 подраздела) | `tools/roles.py` — сторона iam | **нет**: `tools/yaml2fga.py` (рендер модели) читает `seed` **ноль** раз |
| `doc`, `relations`, `tiers`, `subjects` у ресурса | **только** `tools/yaml2fga.py` | **да**: их единственный читатель — рендер модели, то есть ветка A развилки |

При ветке B (один параметрический тип) у этих четырёх ключей читателей **ноль**, и
норма самого эпика — «поле заводится, только когда назван его читатель» — их
удаляет. Написать их схему сегодня значит заплатить за направление, которое ещё не
выбрано: четыре ключа схемы, их утверждения инъекции и ветки загрузчика, которые
их читают.

### 2.5. Манифест в `services/*/` в этой под-фазе НЕ кладётся — и это решение

Соблазн положить `services/vpc/manifest.yaml` вместе со схемой велик: тогда у
гейта дерева появляется популяция. Отвергнуто по двум причинам, каждая
самостоятельно достаточна:

1. **у данных не будет читателя.** Посев iam в этой под-фазе манифест не читает.
   Файл, который приняли и не прочли, есть «принято-и-проигнорировано» на уровне
   артефакта (`api-conventions.md`): продукт обещает возможность, которой нет;
2. **манифест vpc несёт три раздела, которых схема не описывает** (§2.4), и
   загрузчик с `KnownFields(true)` его отвергнет — то есть в дерево уехал бы файл,
   заведомо не проходящий собственную проверку.

**Следствие названо прямо, а не умолчано:** гейт дерева «каждый манифест в
`services/*` разбирается» здесь **не заводится**, потому что его популяция нулевая,
а гейт на нулевой популяции проходит тривиально и **неотличим от исправной работы**
(`testing.md` §«Гейт на класс», п. 9 — негативно-подобное утверждение замолкает, а
не краснеет). Он заводится **вместе с первым манифестом**, задачей-преемником;
предикат его заведения — `git ls-files | grep -cE '/manifest\.yaml$'` перестал
давать ноль.

### 2.6. Загрузчик не вестигиален — у него есть прод-потребитель

Пакет без прод-импортёров подлежит удалению (`architecture.md` §LEAN). Потребитель
загрузчика в этой под-фазе — **цель сборки** (`module-manifest-check`), читающая
каждый манифест дерева и роняющая прогон на негодном. Форма взята у канона
порождённого закоммиченного артефакта, который в дереве уже есть:
`gateway/Makefile` несёт тройку `permission-catalog` · `permission-catalog-apply` ·
`permission-catalog-check` (предикат: `grep -nE '^permission-catalog' gateway/Makefile`
→ строки 68, 75, 86).

**Исходов у цели три, а не два**, и третий обязателен: манифестов ноль — это
**VOID** («проверять нечего»), а не успех. Иначе пустое дерево отчитывается зелёным
ровно так же уверенно, как проверенное.

### 2.7. Загрузчик живёт ВНУТРИ `services/iam` — решение, а не раскладка

Прежняя редакция клала загрузчик в `pkg/manifest` и тем же текстом велела ему спрашивать
`domain.IsKnownModule`. **Так нельзя, и это не вкус, а правило языка**, проверенное
сборкой пробного пакета:

| место пробного пакета | `go build` |
|---|---|
| `pkg/zzprobe` | `use of internal package …/services/iam/internal/domain not allowed` |
| `services/iam/internal/zzprobe` | без вывода — собирается |

Как было написано, MOD-MF-06 вынуждал бы загрузчик нести **вторую копию** перечня модулей
— ровно то, что §2.1 запрещает: два места об одном предмете, расходящиеся молча.

**Решение: `services/iam/internal/manifest`.** Довод не «так собирается», а **чей это
предмет**: манифест — то, что домен объявляет **iam**-у (`apiVersion: iam/v1`, `$id` схемы
— `module-manifest-seed`), и читает манифест iam. Правило фундамента прямое:
«всё горизонтальное (нужное 2+ сервисам) — в `pkg/`; доменная логика живёт в каталоге
своего сервиса» (`architecture.md`). Прод-читателей манифеста вне `services/iam` сегодня
**ноль**, и производитель манифеста не проверяет себя сам — его проверяет **один**
проверяющий по всему дереву (§2.6).

**Цена решения названа, а не умолчана:**

1. **другой сервис не может импортировать загрузчик.** Потребность измерена: читателей
   ноль. Появится второй прод-импортёр вне `services/iam` — переезжает **форма** (разбор
   и структуры) в `pkg/manifest`, а **членство** остаётся у iam. Предикат переезда:
   `git grep -l 'internal/manifest' -- '*.go' ':!services/iam/*'` перестал быть пуст;
2. **гейт дерева `internal/repohygiene` тоже не сможет его импортировать** — правило
   `internal` то же самое. Это не потеря: держатель MOD-MF-17/18/19 — **цель сборки**, а
   не проба repohygiene, и так и было задумано.

**Два отвергнутых исхода — с ценой каждого:**

| исход | почему отвергнут |
|---|---|
| перенести `knownModules` в `pkg/` | это **публикация координаты в публичном репозитории** — а `#1027` назначил этот литерал к **снятию** (каталог становится строками, §2.8). Публиковать то, что удаляют, значит платить необратимостью (ban #18, «перспективность») за ноль потребителей. Плюс правка конфигурации гейта `clienttruth_iam_moduleset_test.go`, который пинит `ModuleSetFile: services/iam/internal/domain/module_set.go` |
| набор приходит загрузчику **параметром** от вызывающего | законно и по существу верно, но здесь **бесплатно не даёт ничего**: внутри `services/iam` держатель и так достижим напрямую. Шов был бы заведён без потребителя, и MOD-MF-06 переехал бы к слою, которого пришлось бы назвать и удержать отдельно. Заводится вместе с переездом формы в `pkg/` (пункт 1 выше), а не раньше |

**Опубликованная схема лежит ВНЕ `internal/`** — `services/iam/schema/module-manifest-seed.schema.json`.
`internal` есть правило видимости **Go**, а не способ хранить файл; но контракт, который
читает автор манифеста и его редактор, не вправе читаться как внутренний. MOD-MF-21
сверяет два адреса — этот и `services/iam/internal/manifest`.

### 2.8. Закрытый набор модулей — решение с ПРЕДИКАТОМ ИСТЕЧЕНИЯ

Проверка «`module` — член закрытого платформенного набора» (MOD-MF-06) **верна сегодня и
перестанет быть верной по известной причине**. Сказано здесь, потому что ban #18
(«перспективность») требует называть, чем решение истечёт, а не только чем оно обосновано.

**Почему закрытый набор сейчас.** Манифест описывает **встроенный** модуль: все шесть имён
набора — модули поставки, и каждое имеет строки в таблицах типов iam. Незнакомый `module`
сегодня означает опечатку либо имя каталога вместо имени модуля (`nlb` против
`loadbalancer`), и оба исхода — дефект манифеста, а не расширение платформы.

**Чем истечёт — предикат, а не намерение.** `#1027` («каталог модуля как данные») ставит
целью, чтобы **клиент** описал свой домен, и называет механизм: каталог перестаёт быть
литералом и становится строками — `catalog_module` / `catalog_resource` / `catalog_verb`
с колонкой `live`. Клиентский модуль по построению **вне** литерала, поэтому вместе с
`#1027` у проверки меняется **предмет**: не «член платформенного набора», а «объявлен
каталогом».

| ось | значение |
|---|---|
| предикат истечения | `git grep -l 'catalog_module' -- 'services/iam/internal/migrations/*.sql'` перестал быть пуст |
| сегодня | **0** файлов (замер на `dc607b06f`) |
| что делать в этот момент | MOD-MF-06 переписывается на чтение строк каталога; `IsKnownModule` снимается **вместе с литералом**, а не остаётся вторым судьёй |
| чем держится до тех пор | `internal/repohygiene/clienttruth_iam_moduleset.go` — он выводит набор **разбором объявления** и потому не переживёт снятия литерала молча |

**Это не отсрочка (ban #11): работа не откладывается, откладывается СМЕНА ПРЕДМЕТА.**
Сегодняшняя проверка полна в своих границах — она отвергает всё, что не член набора, с
названным токеном и названной причиной. Меняется не полнота, а то, у кого спрашивают.

## 3. ЧЕГО ЭТА ПРИЁМКА НЕ РЕШАЕТ — третье объявление прав

Названо здесь, а не спрятано, потому что по ban #18 («благо продукта»,
«перспективность») оно определяет судьбу всего раздела `resources`, и потому что
**преемник без ответа на него заводиться не должен**.

Манифест, объявляющий `resources[].verbs[].class`, есть **третье** объявление
предмета, у которого дерево только что свело два в одно: карта прав сервиса
ВЫВОДИТСЯ из аннотаций proto (`pkg/authz/catalogderive`), каталог края порождается
из тех же аннотаций (`gateway/scripts/gen-permission-catalog.sh`).

Рядом стоит гейт, чьё второе утверждение прямо ловит возврат второго объявления —
`internal/repohygiene/catalogparity_test.go`,
`TestNoServiceDeclaresItsPermissionsASecondTime` (предикат:
`grep -n '^func Test' internal/repohygiene/catalogparity_test.go` → три утверждения,
строки 132, 244, 354).

**Почему он на манифесте НЕ покраснеет — и почему это не оправдание.** Его обход
читает только не-тестовые `.go` и ищет литеральную сборку карты RPC
(`inspectRPCMapConstruction`). YAML не Go: гейт молчит **by construction**. Его
молчание здесь — не отпущение, а слепота другого рода; ссылаться на него как на
подтверждение годности запрещено.

**Исходов три, четвёртого нет** (форма — `api-conventions.md`
§«Принято-и-проигнорировано»):

| # | исход | цена |
|---|---|---|
| 1 | манифест **замещает** аннотации как источник | генератор идёт из манифеста в proto — работа другого размера, чем `#1088` |
| 2 | манифест **выводится** из аннотаций и объявляет только то, чего в них нет (`doc`, `relations`, `subjects`, `tiers`, `seed`) | форма `catalogderive`; раздел `resources` перестаёт быть объявлением |
| 3 | манифест объявлен вторым источником **осознанно** | запись в `services/iam/docs/engineering/architecture/`, а не задача (`git-issues.md` §«By-design отклонение») |

**Раздел `seed` под этот вопрос не подпадает** — аннотации о посеве не говорят
ничего, — и это третий довод класть его первым.

## 4. Out-of-scope — явно

| Не входит | Почему | Куда |
|---|---|---|
| схемы `resources`, `roles`, `deprecatedVerbs` | четыре ключа читает только рендер модели, то есть ветка A развилки `#1104` (§2.4) | **`#1778`** (открыта, `blocked`), после `#1104` |
| **порядок установки модулей, выводимый из `joins`** | свойство **межманифестное**: «раз модуль вступает в группу чужого манифеста, тот идёт раньше». Манифестов в дереве **0** (`git ls-files \| grep -cE '/manifest\.yaml$'`), в черновике несёт `joins` **1**, а группу вступления (`module-quota-readers`) не объявляет **ни один**. Валидатор порядка не может покраснеть ни при каком входе — это гейт на нулевой популяции, неотличимый от исправной работы (§2.5) | преемник; предикат заведения — манифестов в дереве стало **≥2**, и хотя бы один объявляет группу, в которую вступает другой |
| рендеринг модели прав из манифеста | предмет развилки `#1104` | `#1104` |
| исход развилки третьего объявления прав | вопрос о предмете двух источников, не о тексте (§3) | преемник, блокер его заведения |
| манифест в `services/*/` | нет читателя данных; отвергается собственной проверкой (§2.5) | преемник |
| гейт дерева «каждый манифест разбирается» | популяция нулевая, гейт был бы тривиально зелен (§2.5) | преемник, с первым манифестом |
| посев iam, читающий манифест вместо нынешнего источника | это потребитель данных, а не контракта | преемник |
| перенос черновика `tools/*.py` целиком | 9 инструментов, из них рендер модели — предмет `#1104` | по частям, за своими предметами |

## 5. Сценарии

Идентификатор — `MOD-MF-<NN>`, трассируется в имена проб.

### 5.1. Форма: положительные

**MOD-MF-01 — реальный манифест принимается загрузчиком**

**Given** документ, несущий `apiVersion: iam/v1`, `module: vpc` и раздел `seed`,
взятый **дословно** из проверенного черновика — перепись валидатора черновика:
`учётных записей 1 · групп 2 · выдач 2 · вступлений 1`
**When** документ подан загрузчику `services/iam/internal/manifest`
**Then** ошибка — `nil`
**And** значения всех четырёх подразделов `seed` доступны вызывающему
**And** измеренная граница: схема к документу **НЕ ПРИМЕНЯЕТСЯ** — применить её нечем
(`grep -ci jsonschema go.mod` → **0**) и не будет чем по §2.1; согласие схемы со
структурами утверждает **MOD-MF-21**, сличая множества ключей, а не разбирая документ

> Это положительный контроль **всей** §5: без него любое отрицание ниже зеленело бы
> на загрузчике, отвергающем всё. Держат его два первых утверждения — приём документа
> и доступность значений; третье о них не говорит и контролем не является.

> [!note] Здесь стояло требование БЕЗ ПРОИЗВОДИТЕЛЯ — снято по `#1818`
> Третьим «И» стояло требование, чтобы тот же документ **дал ноль замечаний, будучи
> проверен опубликованной схемой**. Исполнить это нечем и не будет чем: библиотеки
> JSON Schema для Go в дереве нет ни одной (`git grep -li jsonschema -- '*.go'` →
> пусто), а сама схема читается **как файл** — `os.ReadFile` в пробе согласия.
> Числа этой врезки сняты на `5dcefe679`, то есть **позже** ревизии измерения из
> шапки: снятие требования проверялось на дереве с уже посаженной реализацией.
>
> Отсрочкой это не было: требование противоречило **§2.1 этого же документа**, где
> схема объявлена контрактом для автора манифеста, а не вторым судьёй формы. Два
> правила об одном предмете, из которых верно одно, — и верно то, по которому написан
> код: проба зовётся `TestMODMF01RealManifestPassesTheLoader`, а её шапка отказ от
> второй половины сценария объясняет дословно.
>
> **Снят и заголовок**, обещавший **двух судей**, а не только текст: он нёс то же
> утверждение в форме, которую поиск по фразе не находит. Строку успели скопировать в
> приёмку `#1778`, где её нашёл рецензент; чинится первоисточник, чтобы копировать
> стало нечего.
>
> **Дословные строки снятого требования и снятого заголовка здесь намеренно не
> воспроизводятся.** Предикат снятия `#1818` считает вхождения этой фразы по каталогу
> приёмок, и цитата в разборе была бы для него неотличима от живого требования —
> проверка краснела бы на собственном объяснении (`testing.md` §«Гейт на класс», п. 4).

**MOD-MF-02 — раздел `seed` может отсутствовать целиком**

**Given** документ с `apiVersion` и `module`, но без ключа `seed`
**When** документ подан загрузчику
**Then** ошибка — `nil`
**And** отсутствие раздела представимо **отдельно** от пустого раздела: вызывающий
различает «`seed` не объявлен» и «`seed` объявлен пустым»

### 5.2. Форма: отрицательные, каждое с парным положительным

**MOD-MF-03 — неизвестный ключ верхнего уровня отвергается**

**Given** документ, где вместо `seed` написано `seedz`
**When** документ подан загрузчику
**Then** отказ, и текст называет **имя поля** (`seedz`) и **номер строки**
**And** парный положительный: тот же документ с `seed` — ошибка `nil`

**MOD-MF-04 — неизвестный ключ на глубине отвергается так же**

**Given** документ, где у элемента `seed.accessBindings[]` вместо `roleId` стоит
`rolelD`
**When** документ подан загрузчику
**Then** отказ, называющий поле и строку **того элемента**, а не корня
**And** парный положительный: `roleId` — ошибка `nil`

> Замер, обосновывающий сценарий: `KnownFields(true)` называет
> `line 7: field clazz not found in type verb` на глубине 3. Отказ на глубине —
> не край и не удача, а измеренное свойство.

**MOD-MF-05 — неизвестный `apiVersion` отвергается**

**Given** документ с `apiVersion: iam/v2`
**When** документ подан загрузчику
**Then** отказ, называющий и полученное значение, и перечень принимаемых
**And** парный положительный: `iam/v1` — ошибка `nil`

**MOD-MF-06 — `module` вне закрытого набора платформы отвергается**

**Given** документ с `module: nlb`
**When** документ подан загрузчику
**Then** отказ; текст называет полученный токен и говорит, что набор закрыт
**And** парный положительный: `module: loadbalancer` — ошибка `nil`

> **Ловушка словаря, ради которой сценарий и написан.** Набор модулей — закрытый
> литерал `knownModules` из **6** имён (предикат:
> `grep -n 'knownModules' services/iam/internal/domain/module_set.go`):
> `{iam, vpc, compute, loadbalancer, registry, storage}`. Токен балансировщика —
> **`loadbalancer`, не `nlb`**, а каталог сервиса зовётся `services/nlb`. Манифест,
> названный по каталогу, разошёлся бы с набором **молча**; это тот же класс, что
> `polyrepo.md` §«Ключ домена и имя каталога — РАЗНЫЕ словари».
>
> Комментарий у самого `knownModules` признаёт, что уже переживал свой предмет:
> «эта строка осталась при пяти именах, когда шестое было добавлено, и разошлась
> молча: проба набора утверждала ЧЛЕНСТВО, а не равенство». Проверка `module`
> обязана ходить в `IsKnownModule`, а не нести свою копию перечня — и **достижим
> он ровно потому**, что загрузчик живёт внутри `services/iam` (§2.7): из `pkg/`
> тот же вызов не собирается, и «своя копия» была бы не ленью, а единственным
> выходом.
>
> **Проверка несёт предикат истечения (§2.8).** Она верна, пока набор — литерал и
> модули встроены; `#1027` переводит каталог в строки `catalog_module`, и тогда
> предмет проверки меняется с «член платформенного набора» на «объявлен
> каталогом». Предикат: `git grep -l 'catalog_module' -- 'services/iam/internal/migrations/*.sql'`
> перестал быть пуст (сегодня — **0**). Сценарий в этот момент **переписывается**,
> а не снимается: манифест с незнакомым модулем обязан отвергаться и после.

**MOD-MF-07 — раздел, который эта под-фаза не описывает, отвергается ЯВНО**

**Given** документ, несущий `resources` (либо `roles`, либо `deprecatedVerbs`)
**When** документ подан загрузчику
**Then** отказ, и текст говорит, что раздел **ещё не описан**, называя
задачу-преемника **номером** — `#1778`
**And** парный положительный: тот же документ без этих разделов — ошибка `nil`

> Это исход 2 запрета «принято-и-проигнорировано»: **отвергать явно**. Молча
> принять и выбросить нельзя — вызывающий получил бы успех и уверенность, что его
> раздел применён.
>
> **Номер, а не слова «задача-преемник».** Координата в тексте отказа — часть
> контракта, и она обязана резолвиться: `gh issue view 1778 -R PRO-Robotech/kacho`
> → открыта 2026-08-31T15:11:26Z, «iam: схема манифеста — разделы `resources`,
> `roles`, `deprecatedVerbs`», метки `blocked P1 size:L area:iam release:modules`.
> Круг 1 объявил такую задачу несуществующей; на момент круга 2 она существует —
> перепись рецензента была верна на его ревизии и устарела в тот же день (§0.5).
>
> Сценарий **снимается** вместе с посадкой схемы этих разделов; предикат снятия —
> `#1778` закрыта артефактом, и схема раздела существует в дереве.

### 5.3. Ключ-нестрока: шесть форм, а не десять из тела задачи

**MOD-MF-08 — булев ключ отвергается по ТЕГУ узла**

**Given** документ, где ключ отображения записан как `true:` (без кавычек)
**When** документ подан загрузчику
**Then** отказ, называющий **номер строки** и то, что ключ не является строкой
**And** тот же исход для `false:`, `null:`, `~:`, `123:`, `0x1f:` — **шесть** форм,
каждая отдельным утверждением

**MOD-MF-09 — законный близнец: те же ключи в кавычках молчат**

**Given** документ, где те же шесть написаний стоят **в кавычках**
(`"true":`, `"null":`, `"123":` …)
**When** документ подан загрузчику
**Then** ошибка — `nil`
**And** значения доступны под своими строковыми именами

> Без MOD-MF-09 проверка MOD-MF-08 зеленела бы на загрузчике, отвергающем всякий
> ключ. Замер близнеца: нестрок по тегу — **0**.

**MOD-MF-10 — `on`/`off`/`yes`/`no` остаются строками и НЕ отвергаются**

**Given** документ, где ключи записаны как `on:`, `off:`, `yes:`, `no:`, `y:`, `n:`,
`On:`, `OFF:`, `Yes:`, `NO:`
**When** документ подан загрузчику
**Then** ошибка — `nil`, все десять доступны как строки

> **Сценарий существует, чтобы неверная посылка не вернулась.** Тело задачи
> называет ровно эти десять как ловушку. На `gopkg.in/yaml.v3` они строки — это
> свойство YAML 1.1, а ядро v3 читает YAML 1.2. Проверка, написанная по тексту
> задачи, была бы **зелена всегда** и не видела бы шести настоящих форм.

**MOD-MF-11 — два написания, дающие один ключ, отвергаются, а не схлопываются**

**Given** документ, где в одном отображении стоят и `null:`, и `~:`
**When** документ подан загрузчику
**Then** отказ (по MOD-MF-08 — оба ключа не строки), и названы **обе** строки
**And** ни одно значение не потеряно молча

> Замер, ради которого сценарий: 17 написанных ключей дают **16** ключей карты.
> `null` и `~` схлопываются в один ключ `nil`, одно значение исчезает **без единого
> признака**. Проверка по тегу узла ловит это до схлопывания — по карте оно уже
> ненаблюдаемо.

**MOD-MF-12 — свойство держится в ДЕКОДЕРЕ, а не позже**

**Given** булев ключ в разделе `seed`
**When** документ проходит полный путь загрузки
**Then** отказ приходит **из разбора**, до валидатора связности
**And** валидатор связности этого входа не видит вовсе

> Замер: типизированная цель `map[string]map[string]string` приводит ключ `true` к
> строке `"true"` с `err == nil`. К моменту связности предмета уже нет — свойство,
> вынесенное туда, было бы вакуумным.

### 5.4. Связность ВЫДАЧ: три свойства, невыразимые схемой

Каждое отрицание — с парным положительным на **том же** документе; порча меняет
ровно одно свойство и оставляет форму годной (§2.3, врезка).

> **Предмет подраздела — `accessBindings` и `groups`, но НЕ `joins`.** У вступлений
> правило связности другое, и применить эти три к ним значит покраснеть на
> неиспорченном манифесте — §5.7. Сказано здесь, а не только там, потому что
> единообразная реализация пишется именно отсюда.

**MOD-MF-13 — `roleId` выдачи обязан существовать среди `roles`**

**Given** манифест, где `seed.accessBindings[0].roleId` = `vpc.nosuchRole` — форма
годна образцу (`^[a-z][a-zA-Z0-9]*\.[a-zA-Z][a-zA-Z0-9]*$`), роли с таким
идентификатором в `roles` нет
**When** манифест проходит валидатор связности
**Then** отказ, называющий и незнакомый `roleId`, и место выдачи
**And** парный положительный: тот же манифест с `roleId` из `roles` — ошибок нет
**And** измеренная граница: опубликованная схема на этом входе **МОЛЧИТ**

**MOD-MF-14 — субъект ВЫДАЧИ обязан быть заведён ЭТИМ ЖЕ посевом**

**Given** манифест, где субъект **выдачи** (`seed.accessBindings[]`) имеет годную форму,
но ни в `seed.serviceAccounts`, ни в `seed.groups` не заведён
**When** манифест проходит валидатор связности
**Then** отказ, называющий субъект и то, каким подразделом он должен быть заведён
**And** парный положительный: субъект, заведённый посевом, — ошибок нет
**And** измеренная граница: схема **МОЛЧИТ**
**And** граница ПРЕДМЕТА: правило относится к `accessBindings`; к `joins.group` оно
**не применяется** — там сторона чужая by construction (MOD-MF-24)

**MOD-MF-15 — заведённая группа обязана быть кому-то выдана**

**Given** манифест, где `seed.groups` несёт группу с годным именем, на которую нет
ни одной выдачи
**When** манифест проходит валидатор связности
**Then** отказ, называющий группу
**And** парный положительный: каждая группа названа хотя бы в одной выдаче —
ошибок нет
**And** измеренная граница: схема **МОЛЧИТ**

> **Почему это отказ, а не предупреждение.** Группа без выдачи — объявление без
> следствия: она заводится посевом, живёт и не даёт ничего. Ровно тот класс, что
> `data-integrity.md` §B18 называет ценой перечисления субъектов. Оставить её
> молча значит завести право, за которым никто не отвечает.

**MOD-MF-16 — контроль связности: неиспорченный манифест молчит**

**Given** раздел `seed` манифеста vpc **дословно**, без правок
**When** манифест проходит валидатор связности
**Then** ошибок ноль
**And** валидатор печатает **объём осмотренного** двумя числами: выдач прочитано ·
субъектов разрешено

> «Ноль находок» обязано быть отличимо от «ноль прочитанного».

### 5.5. Цель сборки: три исхода, не два

> **Почему цель здесь названа именем, а не готовой командой — и почему это НЕ подгонка
> под инструмент.** Гейт `TestNamedMakeTargetExists` считает предметом **только** вызов
> вида `make <цель>` внутри обратных кавычек (`mentionsInSpan`: вызов обязан начинать
> команду). Приёмка садится по ban #1 **прежде** кода, значит на момент её посадки цели
> в дереве нет, и три готовых команды дали бы три находки — измерено, не предположено:
>
> ```
> go test ./internal/repohygiene -run TestNamedMakeTargetExists -count=1
>   → три находки, строки 579 · 586 · 594
>   → осмотрено файлов 8514 · Makefile 13 · целей 119 · упоминаний 280
> ```
>
> Гейт **прав по существу**: документ, предлагающий набрать несуществующее, есть ложное
> обещание, и его собственный текст называет три законных исхода — завести цель · назвать
> ту, что есть · снять упоминание вместе с обещанием. Приёмка выбирает **первый**, но
> разносит его по двум изменениям, потому что обещание и его исполнение садятся в разном
> порядке:
>
> | посадка | что вносится | состояние гейта |
> |---|---|---|
> | **1. эта приёмка** (до кода, ban #1) | цель названа **идентификатором** — `module-manifest-check`; готовой команды нет ни в одной строке | зелёный: предмета нет |
> | **2. изменение, заводящее цель** | цель в `Makefile` **и** тем же изменением — готовая команда в его README/справке | зелёный: цель существует |
>
> Заводить цель-заглушку заранее нельзя: цель, ничего не проверяющая, есть stub (ban #14).

**MOD-MF-17 — годное дерево**

**Given** дерево, где каждый найденный манифест годен
**When** исполняется цель `module-manifest-check`
**Then** код возврата **0**
**And** напечатано число прочитанных манифестов

**MOD-MF-18 — негодный манифест роняет прогон**

**Given** дерево, где один манифест несёт незнакомый `module`
**When** исполняется цель `module-manifest-check`
**Then** код возврата **1**
**And** назван путь файла, поле и строка
**And** назван способ починки

**MOD-MF-19 — манифестов ноль есть VOID, а не успех**

**Given** дерево, в котором манифестов нет ни одного
**When** исполняется цель `module-manifest-check`
**Then** код возврата **отличен и от 0, и от 1**, и вывод говорит «проверять
нечего»
**And** вывод **отличается по тексту** от вывода при годном дереве

> Третья категория (`testing.md` §«Чтение вердикта») в успех не засчитывается. Без
> неё пустое дерево отчитывается зелёным ровно так же уверенно, как проверенное —
> а сегодня дерево именно пустое (манифестов **0**).

**MOD-MF-20 — изменение, заводящее цель, заводит и её ГОТОВУЮ КОМАНДУ**

**Given** изменение, вносящее цель `module-manifest-check` в `Makefile`
**When** исполняется `internal/repohygiene` `TestNamedMakeTargetExists`
**Then** прогон зелёный
**And** в том же изменении есть **хотя бы одно** упоминание готовой командой
(вызов `make` с этой целью внутри обратных кавычек) — иначе гейт держит **ноль**
упоминаний этой цели, и его молчание о ней неотличимо от исправной работы

> **Сценарий переписан в круге 2, и вот почему.** Прежняя редакция объявляла: «приёмка
> попадает под гейт автоматически, заводить ничего не надо». Измерено — попадает, и
> роняет дерево тремя находками (врезка выше). Но и обратная правка (убрать готовые
> команды и оставить сценарий как был) сделала бы MOD-MF-20 **вакуумным**: у гейта не
> осталось бы ни одного упоминания этой цели, то есть утверждения без производителя
> входа. Поэтому предмет сценария перенесён с приёмки на **изменение, заводящее цель**:
> там производитель входа есть by construction.
>
> Гейт существует (предикат:
> `grep -n '^func Test' internal/repohygiene/namedmaketarget_test.go` →
> `TestNamedMakeTargetExists`, строка 190).

### 5.6. Согласие схемы и структур

**MOD-MF-21 — множество ключей схемы РАВНО множеству полей структур**

**Given** опубликованная схема `services/iam/schema/module-manifest-seed.schema.json`
и Go-структуры `services/iam/internal/manifest`
**When** исполняется проба согласия
**Then** множества совпадают — **равенство**, а не членство
**And** проба печатает оба числа: ключей схемы · полей структур

> **Равенство, а не членство** — потому что членство уже подводило в этом самом
> дереве: проба `knownModules` утверждала членство и не сопротивлялась росту
> набора, из-за чего комментарий разошёлся с литералом молча (§5.2, MOD-MF-06).
>
> Эта проба — единственная причина, по которой схему вообще можно держать рядом со
> структурами. Без неё два места об одном предмете разойдутся, и разойдутся там,
> где не видно: оба отвечают «валидно» на валидном входе.

**MOD-MF-22 — у каждого ключа схемы назван читатель**

**Given** перечень ключей опубликованной схемы
**When** по каждому исполняется
`git grep -c '"<ключ>"' -- 'services/iam/internal/manifest' ':!*_test.go'` —
единица счёта **прод-файлов-читателей**, шт.
**Then** ни один ключ не даёт ноль

> Ключ без читателя — «принято-и-проигнорировано» и обещание без ответчика
> (ban #11). **Число снимается только после реализации** — сегодня оно не
> существует, и приёмка это говорит прямо, а не подставляет ноль.

### 5.7. Связность `joins`: правило ДРУГОЕ, чем у выдач — и это по построению

Отдельным подразделом, а не строкой в §5.4, потому что единообразное правило здесь
**неверно**: применённое к `joins`, оно краснеет на собственном положительном контроле
MOD-MF-16. Замер — §0.2; коротко: вступают в **чужую** группу, объявленную другим
манифестом, и валидатор черновика (`tools/roles.py`, строки 309–333) уже требует стороны
по-разному, а схема объясняет это описанием поля.

**MOD-MF-23 — служебная запись вступления обязана быть заведена ЭТИМ посевом**

**Given** манифест, где `seed.joins[].serviceAccount` имеет годную форму (пара `account`,
`name`), но такого имени нет в `seed.serviceAccounts`
**When** манифест проходит валидатор связности
**Then** отказ, называющий имя записи и подраздел, которым она должна быть заведена
**And** парный положительный: запись из `seed.serviceAccounts` — ошибок нет
**And** измеренная граница: опубликованная схема на этом входе **МОЛЧИТ** (пара форму
проходит)

**MOD-MF-24 — ЧУЖАЯ группа вступления НЕ отвергается: это законный близнец, а не дыра**

**Given** манифест vpc дословно: `seed.joins[0].group` = (`system`,
`module-quota-readers`), и такой группы в `seed.groups` **нет** (посеяны
`vpc-internal-consumers`, `cloud-network-admins`)
**When** манифест проходит валидатор связности
**Then** ошибок ноль
**And** правило MOD-MF-14 («субъект выдачи заведён этим же посевом») к `joins.group`
**не применяется** — и это утверждается сценарием, а не подразумевается

> **Это самый важный отрицательный контроль раздела**, и без него он вреден. Валидатор,
> написанный единообразно, покраснел бы **здесь** — на неиспорченном манифесте, — и его
> красное прочли бы как дефект данных. Замер: `python3 roles.py ../vpc.manifest.yaml`
> → `ВЕРДИКТ: целостно` при `вступлений 1`, чья группа в посеве отсутствует.
>
> Почему так задумано, сказано схемой поля: «владелец своих потребителей не знает и знать
> не должен» — членство заявляет **вступающий**, а не перечисляет владелец группы.

**MOD-MF-25 — вступление без причины отвергается**

**Given** манифест, где у `seed.joins[]` нет ключа `why` либо он короче объявленного
предела
**When** манифест проходит валидатор связности
**Then** отказ, называющий вступление и то, что не сказано, ЗАЧЕМ вступаем
**And** парный положительный: то же вступление с причиной — ошибок нет

> Не косметика: членство без причины **некому снять** — следующий не знает, действует ли
> ещё основание. Тот же класс, что `data-integrity.md` §B18 («право, за которым никто не
> отвечает»).

**MOD-MF-26 — обе стороны вступления адресуются ПАРОЙ, одно имя не адресует**

**Given** манифест, где `serviceAccount` либо `group` записаны одной строкой вместо пары
(`account`, `name`) — либо в паре нет одного из двух ключей
**When** манифест проходит валидатор связности
**Then** отказ, называющий сторону и недостающий ключ
**And** парный положительный: обе стороны парами — ошибок нет

> Уникальность в продукте держат `groups_account_name_unique` и
> `service_accounts_account_name_unique` — **пара**, а не имя. Прежняя редакция черновика
> писала `iam/module-quota-readers`, смешивая МОДУЛЬ (кто завёл) с АККАУНТОМ (где лежит),
> и не отвечала, в чей аккаунт вступают. Аккаунты сторон **смеют различаться**:
> `group_members` связи с аккаунтом не несёт вовсе, то есть межаккаунтное членство схемой
> продукта разрешено — потому оба аккаунта пишутся, а не выводятся.

### 5.8. Набор инъекций обязан ИСПОЛНЯТЬСЯ без аргументов

**MOD-MF-27 — набор, запущенный без аргументов, исполняет ВСЕ свои утверждения**

**Given** набор инъекций, перенесённый в дерево (на Go, §9.3)
**When** он исполняется обычным `go test` без единого аргумента
**Then** число исполненных утверждений равно числу объявленных
**And** ноль утверждений в состоянии «не выполнилось»
**And** парный отрицательный: изъятие входа у одного утверждения делает прогон
**красным**, а не пустым

> **Сценарий заведён кругом 2 и держит предмет, у которого до сих пор не было держателя.**
> Набор черновика по умолчанию даёт `утверждений: 38 · прошло: 0 · провалено: 38` (причина
> в его выводе — путь `../vpc.yaml` при файле `vpc.manifest.yaml`). Это не «зелено» и не
> «красно», это третья категория, поданная как красное: **все** утверждения не
> исполнились. Перенесённый как есть, набор дал бы ложное красное на первом же прогоне.
>
> Почему сценарий, а не строка «починить при переносе»: обещание без держателя не
> отличается от невыполненного. Здесь держатель — само утверждение о числе исполненных.

## 7. Обязательность ключей — популяция ОДИН, и это сказано прямо

Схема выводится из **одного** манифеста. Частота ключей ресурса (единица счёта —
**ресурсов, несущих ключ**, из 10):

| ключ | частота | что из этого следует |
|---|---|---|
| `name` · `parent` · `verbs` | **10/10** | обязательность правдоподобна |
| `relations` | **2/10** | популяция мала |
| `doc` · `subjects` · `tiers` | **1/10** | **предпосылка не подтверждена**: n=1 |

Узкая популяция предпосылку не подтверждает, она её **скрывает**
(`testing.md` §«Гейт на класс», п. 3). Поэтому:

**Решение.** Обязательность каждого ключа раздела `seed` называется **решением с
причиной**, а не выводится из частоты в vpc. Для ключей частоты 1/10 в схеме стоит
комментарий: «популяция 1, обязательность не выведена, а назначена». Ключи
ресурса в объём этой под-фазы не входят (§4) — их обязательность решает преемник,
на популяции, которая к тому времени, возможно, станет больше единицы.

**Чем держится:** ничем машинным — этой записью и вердиктом рецензента.

## 8. Форма артефактов и гейты дерева, которые обязаны их увидеть

Область гейта лицензионных шапок измерена (предикат:
`sed -n '45,82p' internal/repohygiene/license_test.go`):

- **в области:** `.go` `.sql` `.sh` `.py` `.yaml` `.yml`, а также файл с базовым
  именем `Makefile`;
- **вне области:** `.json`, `.md`; плюс любой путь, где есть сегмент `.git`,
  `.claude`, `docs`, `node_modules`, `vendor`, `bin`.

**Решение по форме схемы: `.json`.** Два довода, оба проверяемы:

1. документ JSON Schema комментария не несёт **вовсе**; `.yaml`-форма заставила бы
   вносить SPDX-шапку в артефакт, у которого для неё нет места в целевом формате;
2. потребитель схемы вне Go — редактор автора манифеста — читает `.json` без
   преобразования.

Если владелец предпочтёт `.yaml` — шапка `# SPDX-License-Identifier: BUSL-1.1`
обязательна, и это не пожелание: гейт существует.

## 9. Способность проверок УПАСТЬ — как доказывается

Наборы инъекций переезжают в дерево вместе с артефактами; **зелёный прогон
доказательством не является**.

### 9.1. Форма доказательства

По каждому утверждению — **три** прогона, а не два
(`testing.md` §«Гейт на класс», п. 2в):

1. **контроль** — ничего не испорчено: молчат все проверки;
2. **инъекция проверяемого** — испорчено **ровно одно** свойство, форма остальных
   годна: краснеет **только** проверка этого свойства и называет координату;
3. **законный близнец** — конструкция той же формы, но законная: проверка молчит.

**Инъекция, роняющая не то, доказательством не является.** Врезка §2.3 — живой
пример: первые три моих порчи связности покраснели **на форме** (образец имени,
перечень свойств), а не на связности, и «краснеет» ничего не значило.

### 9.2. Что должна показать инъекция по каждой оси

| ось | инъекция | законный близнец |
|---|---|---|
| неизвестный ключ | `seedz` вместо `seed` | `seed` |
| неизвестный ключ на глубине | `rolelD` вместо `roleId` | `roleId` |
| `apiVersion` | `iam/v2` | `iam/v1` |
| `module` | `nlb` | `loadbalancer` |
| ключ-нестрока | `true:` `false:` `null:` `~:` `123:` `0x1f:` — **шесть отдельных** | те же шесть **в кавычках** |
| «не ловушка» | — | `on: off: yes: no: y: n: On: OFF: Yes: NO:` — молчат все десять |
| `roleId` вне `roles` | `vpc.nosuchRole` (форма годна) | `roleId` из `roles` |
| субъект не заведён | субъект годной формы вне посева | субъект из посева |
| группа без выдачи | группа годного имени, выдач ноль | та же группа, названная в выдаче |
| раздел не описан | документ с `resources` | документ без него |
| запись вступления не заведена | `joins[].serviceAccount.name` вне `seed.serviceAccounts` | имя из `seed.serviceAccounts` |
| **чужая группа вступления** | — (инъекции НЕТ: отвергать нечего) | группа вне `seed.groups` — валидатор **молчит** |
| вступление без причины | `why` снят либо короче предела | `why` названа |
| сторона вступления не парой | `serviceAccount: kacho-vpc` строкой | пара (`account`, `name`) |

### 9.3. Наборы инъекций обязаны ИСПОЛНЯТЬСЯ — а сегодня не исполнились бы

Наборы черновика питоновы; прогонщик проб берёт их по узкому образцу:

```
grep -n 'DEFAULT_PATTERN' .github/scripts/run-python-probes.py
  → DEFAULT_PATTERN = "services/*/tests/newman/scripts/*_test.py"
git ls-files | grep -cE '_test\.py$'   → 12   (проб, шт.)
```

Ни один из трёх наборов черновика (`roles-inject.sh` · `schema-inject.py` ·
`inject.sh`) под образец **не подпадает ни именем, ни местом**. Исходов два:
расширить образец **со своим гейтом провязки** либо переписать наборы на Go.
**В объёме задачи это не учтено** — работа существует и должна быть названа.

**Решение приёмки: переписать на Go.** Тогда наборы исполняются обычным
`go test`, попадают под те же гейты дерева, что и остальной корпус, и не требуют
ни расширения образца, ни второго гейта провязки, за которым надо следить.

### 9.4. Дефект «0 из 38» — предмет есть, но у него ДРУГОЙ носитель и другая судьба

Прогон автора на круге 2: `bash roles-inject.sh` без аргумента → «утверждений: 38 ·
прошло: 0 · провалено: 38», код возврата 1; причина в выводе — набор копирует
`../vpc.yaml`, тогда как манифест зовётся `vpc.manifest.yaml`. С явным путём — 38 из 38.

**Ссылка на ws#478 снята: это была задача с другим предикатом.** Её предмет — «черновик
существует в одном экземпляре и вне git», её предикат снятия —
`git ls-files docs/manifest-dcl | wc -l` не ноль **либо** каталог осознанно снят
(прочитано целиком: `gh issue view 478 -R PRO-Robotech/kacho-workspace`). Закрытие ws#478
дефект 0/38 **не закрывает** ни при каком исходе: каталог может быть сдан вместе с
неисполнимым набором. Ссылаться на неё здесь значило бы объявить предмет заведённым, не
заведя его, — а это форма без содержания.

**Куда предмет девается на самом деле: он умирает вместе с носителем.** §9.3 решает
переписать наборы на Go; `roles-inject.sh` в дерево **не переносится вовсе**, значит
чинить в нём нечего. Но переживает носителя **свойство**, ради которого дефект и
показателен: набор обязан исполнять свои утверждения без аргументов, иначе «не
выполнилось» подаётся как красное.

**Держатель у свойства теперь есть — MOD-MF-27** (§5.8): число исполненных утверждений
равно числу объявленных, и изъятие входа даёт красное, а не пустое. Это исполнение
предиката замечания Р4 («названа задача, чей предикат описывает 0/38, либо §9.4 говорит,
что предмета нет, и заводит его») — предмет заведён **сценарием приёмки**, а не ссылкой на
чужую задачу: сценарий лежит в том же документе, что и решение, и снимается вместе с ним.

**Перенос набора «как есть» приёмкой ЗАПРЕЩЁН**, а не «не рекомендуется»: он вносил бы в
дерево набор, заведомо не проходящий собственный прогон.

Заодно: README черновика называет 38 утверждений, тело `#1088` — 34. Верно **38**.
