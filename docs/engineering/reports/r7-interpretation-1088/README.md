## Сохранность и обратное восстановление

`originalSHA` относится к raw, `newSHA` — к исправленному отчёту.
Каждый manifest хранит старые и новые байты замен, их длины, SHA и смещения,
хеши неизменяемых диапазонов и точное добавленное приложение. `newSHA` находится
в отдельном manifest, без самоссылки внутри отчёта.

Для независимого восстановления исходного файла:

1. Сверить SHA256 raw с `originalSHA`, отчёта с `newSHA`, плана с `planSHA`.
2. Декодировать `addition.bytesBase64`, сверить длину и SHA, проверить точное
   совпадение с концом отчёта от `addition.newOffset` и удалить это добавление.
3. Пройти `edits` в обратном порядке. На каждом `newOffset` проверить точные
   новые байты, длину и SHA, затем заменить их декодированными старыми байтами.
4. Сравнить восстановленные байты со всем raw, а не только его числовыми строками.
5. Отдельно сравнить все `preservedSpans` по исходным и новым смещениям,
   длинам, SHA и полному содержимому. Это включает таблицы и provenance.

Для прямого восстановления пройти разрешённые замены от исходных смещений
плана, сохраняя весь остальной raw, и добавить точные `addition` из manifest.
Результат должен совпасть с опубликованным исправленным отчётом побайтно.
Фрагменты плана и manifest позволяют сделать обе операции без повторного замера
и без зависимости от исходного преобразователя.

[SHA256SUMS](SHA256SUMS) содержит пины этого пакета и четырёх отчётов.
Команду следует выполнять из данного каталога:

```bash
sha256sum --check SHA256SUMS
```

## Область исправления и свидетельства приёмки

R7-1 сохраняет все исходные значения SQL-захвата, отдельно объясняя вклад
запроса прибора и производный продуктовый счёт. R7-2 разделяет сценарии,
вызовы, выборки времени и EXPLAIN; сохранённый начальный исход не объявляется
автоматическим assertion ожидаемого результата. Доля доступных Pg относится
к bulk-объектам и оставляет фиксированный allow. R7-3 выводит стоимость по
объявленной метрике touched и ограничивает выводы о планах и времени.
Writer отделяет модельный порог от чтения реальной гистограммы.

Итоговая независимая приёмка четырёх представлений и интерпретаций передана
диспетчером для переноса в дерево: проверка сохранности — 55 из 55;
проверка кода — три фазы, пять PASS и один ожидаемый FAIL инъекции.
Ожидаемый отказ инъекции не является отказом исправленного кода.
Эти исходы относятся к принятым артефактам и соответствующим экспериментам;
перенос файлов не объявляется новым прогоном измерителя.
